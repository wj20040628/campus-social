项说明
可见范围所有人（含非成员）。成员构成是圈子的公开信息 —— 想加入的人当然想知道里面都有谁。
分组圈主 / 管理员 / 成员 三段，圈主在最上。角色的价值在于「出问题找谁」，所以顺序不能乱。
每行信息头像 + 昵称 + 年级·学院 + 角色标签。不显示学号（SPEC AC-12）。
入口圈子头的「N 成员」变成可点；桌面右栏加「查看全部成员」。
成员操作普通成员那几行右侧是「私信」。圈主/管理看到的还是原来那套（封禁/任命/移出），复用现有面板的按钮，不重做。
为什么不用弹窗。成员多的时候（几十人）弹窗里滚动很难受， 而且「看成员」是一个可能反复回来看的页面（找人、看谁在）。 独立页可以返回、可以分享、可以被浏览器记住位置。

4必须说清的隐私取舍

数据给谁看理由
圈子成员：昵称 + 年级/学院 + 角色所有人圈子是公开组织，「里面有哪些人」是加入决策的一部分。不含学号、不含联系方式。
活动参与者：昵称 + 头像所有人线下见面的活动，知道同去的是谁直接关系安全。只给昵称与头像，同样不含学号。
被封禁的成员不进公开列表封禁是管理措施，不该把人挂在公开成员页上示众。圈主/管理在管理面板里仍能看到。
「私信」按钮仅已认证用户复用现有 @RequireVerified：未认证用户点击时给「去认证」提示，不是静默失败。
一个需要你确认的点：活动参与者要不要对非成员也可见？ 我建议可见（同圈成员和访客都能看到），理由是「知道谁去」直接影响来不来。 但如果你希望只有报了名的人才能看到名单，那需要在后端加一层判断 —— 告诉我，我改。

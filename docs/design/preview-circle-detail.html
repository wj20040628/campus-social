圈子详情页 · 优化方案

基于实测数据。手机端整页 1688px、空态区占 443px（近一半），而页面只有一个输入框和一句话。

1实测：页面为什么显得空

以「444」这个空圈子为例 —— 它只有 1 个成员、0 帖子、0 活动，恰好暴露了空态的排版问题。

1
空态占 443px 高：图标 40 + 标题 + 副句 + 按钮 + 上下各 60px 内边距。它比上面的发帖框还高，视觉重心落在「没内容」这件事上，而不是「你可以发」。
2
「发第一条」与输入框职责重叠：输入框就在正上方，按钮点下去只是聚焦那个框。用户得先意识到「原来这两个是一回事」。
3
视频格式提示整段铺开：mp4 / webm / mov / mkv（H.264 编码）, 单条≤25MB; 不支持 H.265/HEVC —— 两行 10.5px 灰字，压在发帖按钮下方。它只在**真的要传视频**时才有用，平时是噪音。
4
桌面端右侧 600px 全空：内容列 640px 固定，1512 视口下右侧一片空白。这个圈子的信息量（1 成员、0 帖）确实少，但空白不该是「没设计」的样子。

3视频格式提示：从常驻两行改成一个「?」

现在这两行常驻在发帖框里，但只有真要传视频的人才需要它。

现在
视频支持 mp4 / webm / mov / mkv（H.264 编码），单条 ≤ 25MB；不支持 H.265/HEVC

占两行、10.5px 灰字常驻。用户每次打开发帖框都读到它，但 99% 的时候不传视频。

改后
🖼 添加图片或视频 ?

常态只留一个 ?，点开才展开完整说明；上传失败时直接报具体原因。

为什么可以删。这类限制说明的最佳出现时机是失败那一刻 —— 用户选了 H.265 视频，弹「这个编码不支持，请转成 H.264」比事先念一遍规则有用得多。 而现有代码里已经有这条提示了（CircleComposer.vue:139），常驻那段其实是重复的。

集市 · 交互逻辑重设计

针对你指出的三个问题：①标满员与暂停语义重叠 ②过期的活动仍有「标满员」按钮 ③广场上认不出自己的活动

核心结论：现在的四态设计有语义冲突，需要把「为什么下架」和「下架后的效果」分开定义。

1为什么「标满员」和「暂停」重复了

广场查询的过滤条件是四个字段 AND，其中两个是互斥的开关。

现状广场 SQL

WHERE soft_delete=0
AND is_enable=1 ← 暂停
AND is_full=0 ← 满员
AND expire_time > NOW()

  • is_enable=0（暂停）→ 广场消失
  • is_full=1（满员）→ 广场消失
  • 两者对广场的效果完全相同
  • 区别只在「我的发布」里显示的状态文案不同

问题本质两个词是两件事

「满员」是业务事实（人找齐了），「暂停」是运营动作（我先藏起来）。

  • 满员 = 不该再收人，但信息仍有价值（别人能看到这条已经成团，也许下次）
  • 暂停 = 我现在不想让别人看到
  • 把两者都做成「从广场消失」，等于取消了「满员」这个状态的存在意义
用户视角的真实矛盾：一条活动标了满员，它就消失了 —— 那和直接暂停有区别吗？没有。所以「标满员」按钮除了换一个状态文案，没有任何实际作用。

2过期的活动为什么还能「标满员」

这是操作可用性与状态不相关导致的：按钮只看 is_full，不看 expire_time。

活动状态现在显示的按钮实际有意义吗
投放中置顶 / 下架 / 编辑 / 谁还没看有意义
已满员取消满员 / 暂停 / 编辑 / 删除有意义
已暂停开启 / 标满员 / 编辑 / 删除有意义
已过期标满员 / 取消满员 / 编辑 / 删除无意义

过期的活动已经在广场上看不到、也收不到人了 —— 此时「标满员」等于给一具尸体盖章。 真正该出现的只有：重新激活 和 删除。

4重设计：状态与「可见性」解耦

把 is_enable（我是否想展示）和 is_full（人是否已找齐）分开表达，而不是让它们都等价于「下架」。

投放中 → 标满员 → 已满员 → 取消满员 → 投放中
投放中 → 暂停 → 已暂停 → 开启 → 投放中
任意进行中 → 到期 → 已过期 → 重新激活 → 投放中

关键差异：满员后还在广场，但标记为「已满」

状态 广场可见 可留言 设计理由
投放中 是是 正常状态
已满员 是（带「已满」角标）是 这是核心改动。满员是业务事实，信息仍有价值：别人能看到「这条已经成团了」，也许下次会找同一个人。让它消失等于白发了这条。
已暂停 否否 用户主动要求隐藏。这是唯一「真的从广场消失」的状态。
已过期 否是（仅已进入的人） 时间到了自然下架。历史留言仍可查看、可回复，但不再接收新的人。
这个改动需要后端配合一处：广场 SQL 去掉 AND is_full = 0，改成返回满员活动并在 VO 里带 isFull（已有字段），前端据此显示「已满」角标并禁用加入入口。

5按钮只在有意义的时刻出现

每个状态下最多 3 个按钮，且只有真正能改变结果的才显示。

投放中 还剩 2 时 46 分

「标满员」（人找齐了）与「暂停」（先藏起来）现在是两个不同目的的动作，并列出现才有意义。

已满员 仍在广场展示，带「已满」角标

满员时不再提供「置顶」——已经不再收人，置顶没有意义。

已暂停 广场上不可见

暂停时不给「标满员」——藏起来的东西不需要再声明人找齐了。这解决了你现在看到的「暂停态还挂着标满员」的错位。

已过期 10-20 08:16 结束

这就是你指出的 bug：过期活动现在还有「标满员 / 取消满员」。过期后它既不在广场、也收不到人，「标满员」没有任何作用。只保留重新激活与删除。

✓
不再有「无意义按钮」：每个按钮都对应一个当前状态下真实会发生的改变。反过来，不该出现的状态组合直接不渲染，而不是渲染后禁用。
✓
破坏性动作固定在最右且标红，与其它操作之间有分隔线，避免误触。

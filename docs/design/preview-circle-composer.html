1常驻发帖框的四个代价

1
抢占首屏最贵的位置：它在 Tab 正下方、帖子列表上方，是视线第一落点。这个位置该给内容，不该给一个空输入框。
2
框比帖子还显眼：发帖框有边框 + 内边距 + 上传按钮 + 字数 + 提示，视觉重量明显大于一条帖子卡片。于是「能不能发」压过了「别人说了什么」。
3
空态被迫往下挤：框占掉 260px，空态只剩一半空间，于是它被压缩、又被撑大，两种都不好看。
4
每个访客都看到「发表框」：但发帖是低频动作。看的人远多于写的人，却让所有人先看到一张表单。

两种入口的关系
场景显示什么点击后
有帖子顶部一行触发条打开抽屉 / 弹窗
没有帖子空态 + 「写第一条」，不显示触发条打开同一个抽屉
空态时不再重复放触发条。空态里已经有一个「写第一条」按钮， 上面再加一条「写点什么」就是同一个动作出现两次 —— 这正是现在「发第一条」与输入框重复的老问题。 两者只留其一：有内容时用触发条，没内容时用空态按钮。
「写第一条」按钮保留是有规范的。AC-19 要求空态必须有「一句人话 + 一个可点行动按钮」。 去掉常驻框不等于去掉空态按钮 —— 它现在是空态里唯一的发帖入口，反而更重要了。

## 1. 设计调研

### 1.1 调研对象与结论(不是截图描述,是可执行的设计判断)

#### 竞品 A:小红书(RedNote)——生活方式内容社区

**观察到的事实**:双列瀑布流、品牌红 `#FF2442`、种草卡片、图片占卡片 70% 面积;2024 版设计系统已固化为「奶油粉底 + 12px 圆角卡片 + Noto Sans SC 中文优先字体栈 + 胶囊 CTA」。

**对友声的结论(可执行的判断)**:
- **不采用瀑布流**。小红书的信息密度是靠「图」撑起来的——用户刷的是封面。友声的内容主体是「一个人 + 一句具体的话」(求搭子、吐槽、找同好),图片是附带的。照搬双列瀑布流会产生两种后果:一是大量无图条目变成空卡片,二是「那句话」被压缩到 14px 两行以内,恰恰是最关键的信息被牺牲掉。
- **采用的部分**:话题标签作为内容索引(友声的圈子/话题沿用这个心智);手机上双列的高浏览效率——但用在**图片九宫格**上,不用在 Feed 上。
- 结论落地:`VISUAL_DENSITY = 6`,Feed 用**单列 + 1px 分隔线**分组,帖子里的图片才用双列/三列网格。

#### 竞品 B:搭子类产品(咕哇找搭子 / 搭子社交 / Cojoy / CPnow)——青年兴趣结伴

**观察到的事实**:这一整类产品(2025-2026 集中出现)有三个高度一致的共同点:
1. **社交被绑定到一个具体活动上**,而不是绑定到一个「人」上。典型条目是「周五下午三点三号场,缺两个人,来吗」,而不是「男 / 20 岁 / 喜欢运动」。
2. **破冰靠系统给话术,不靠空白输入框**。Cojoy 的产品逻辑写得非常直白:「两个拥有相同标签的人相遇,天然就拥有了共同话题」「不需要绞尽脑汁想开场白」。
3. **信任基建前置**:实名 / 人脸 / 学历 / 人工多重认证是这类产品的标配卖点,不是可选项。

**对友声的结论(可执行的判断)**:
- **G2 的列表单元必须是「一个具体的邀约」,不是「一个人」**。这是本次调研最有价值的一条。昵称和头像降为次要信息(13px),「那句具体的话」升为 16px 主信息。
- **G1 的破冰卡必须预填候选话术**,且话术由「共同标签 + 来源上下文」生成。空白输入框 = 把最难的一步推给用户 = 转化率杀手。
- 认证信息必须在**破冰卡的头部**可见(学院/年级/认证标记),因为这是大学生判断「该不该回」的第一依据。

#### 竞品 C:校园场景设计指南(校园社交平台开发指南 / 大学生社交平台策划)

**观察到的事实**:校园场景有三个硬约束被反复提及——
1. 使用时机是**课间、自习间隙**,单次使用 2-5 分钟,不是沉浸式长时间刷。
2. 校园网环境下**页面加载需控制在 2 秒以内**;学生对流量敏感。
3. 「信息分散、错过活动」是校园场景的核心痛点,官方信息的一站触达是刚需。

**对友声的结论(可执行的判断)**:
- 首页**不允许有任何引导页、教程、新手指引**。第一屏直接是内容。
- **字体必须零下载**(见第 5 节)。加载预算里不给 Web Font 留任何位置。
- G3 官方通知是**刚需而非锦上添花**,必须在首页有一级入口(公告条),不能只埋在通知页里。

#### 参考 D:Linear / Notion / Vercel —— 信息密度与克制感

**观察到的事实**:这三家的共同做法不是「好看」,而是**组织信息的方式**:用 1px 分隔线和负空间分组,而不是给每条数据套一个卡片盒子;中性色占 85% 以上,强调色每屏只出现 1-2 处。

**对友声的结论(可执行的判断)**:
- Feed 与找搭子清单**一律用 `border-top: 1px solid var(--ys-border-soft)` 分组**,不用卡片盒子。这同时规避了「相同卡片网格无限重复」这个 AI 味特征。
- 强调色使用预算写进红线(每屏 ≤2 处),这是能靠肉眼 + 走查快速验证的规则。

#### 趋势 E:2025-2026 UI/UX 趋势(多来源交叉)

采纳三条,拒绝三条:

| 趋势 | 判断 | 理由 |
|---|---|---|
| 分区设计(便当格 / Bento) | **采纳,降级使用** | 首页用分区(公告条 / 兴趣入口 / Feed),但不用「不同大小瓷砖拼网格」的花活,那是展示型页面的语法,不适合高频 Feed |
| UX 文案说人话 | **采纳,强要求** | 与本次「禁止空洞占位文案」红线一致。错误提示写「网络好像断了,点这里重试」,不写「操作异常」 |
| 暗色模式从冷黑转向暖灰低对比 | **采纳方向,但不进 MVP** | 若做暗色,底用 `#111721` 而非纯黑(已在 Token 预留并实测对比度) |
| 动态排版(文字会跳舞) | **拒绝** | 高频使用产品,动效必须传达含义而非吸引注意 |
| 模糊与颗粒滤镜 | **拒绝** | 装饰性模糊是无功能目的的性能负担,与 2 秒加载预算冲突 |
| 3D 元素 / 沉浸式 | **拒绝** | 校园网 + 中低端安卓机,3D 是加载预算和续航的双重灾难 |

## 2. 设计语言与对标品牌

### 2.1 对标

**主对标:Notion(分区秩序 + 中性克制) × 校园公告栏(物理隐喻)**

选「校园公告栏」作为物理隐喻,而不是选另一个 App,是因为它同时满足三个约束:

1. **秩序**:公告栏是分格的、有边界的、按来源分区的——这直接对应「官方通知 / 找搭子 / 帖子流」三大板块的分区语法,也对应「用 1px 线分组」的做法。
2. **直白**:公告栏上的每张纸都写着一句具体的事(「本周六下午两点,三号场,缺两个人」),没有形容词。这直接对应 G2 的列表单元设计——**主信息是那句具体的话**。
3. **可信**:公告栏是公共的、署名的、有来源的。这对应 G3 官方通知的「深墨徽章 + 来源机构」设计。

**副对标:Stripe(克制的强调色预算)、Linear(150ms 动效收敛值)**

### 2.2 设计语言名称

**「公告栏 · 纸面秩序」(Bulletin Board Order)**

- 视觉关键词 3 个:**秩序、直白、轻**
- 氛围描述:冷调浅灰底上浮着白色内容区,区块之间靠 1px 线和留白分隔,唯一的彩色是「友声青」的 CTA 与选中态。看起来像一个整理得很好的公告栏,不像一个要说服你买东西的落地页。
- 品牌声音词(物理对象):**手写的社团招新海报 / 教务处打印的 A4 通知 / 课间操场的扩音喇叭**——手工感、印刷秩序、公共扩音。

### 2.3 反面:我们明确不做「XX 感」

写反面和设计本身同等重要。以下 5 条,任何一条在评审中被发现,该方案退回。

| 不做 | 为什么 |
|---|---|
| **不做小红书感**(双列瀑布流 + 品牌红 + 种草卡片) | 友声的内容主体是「人 + 一句具体的话」,不是图。瀑布流会牺牲最关键的那句话,并产生大量空图卡片 |
| **不做 Soul / 探探感**(暗色霓虹 + 头像卡左右滑) | 校园场景的核心资产是「可验证的身份 + 官方信息」。暗色霓虹直接削弱官方通知的权威感,也与白天教室/图书馆的使用环境冲突 |
| **不做微信 / QQ 感**(纯功能灰绿 + 无尽同质列表) | 会失去「校园」的地域与兴趣属性。用户看不出这里的人和外面的人有什么不同,产品就没有存在理由 |
| **不做 AI 模板感**(紫->粉渐变 + 毛玻璃 + 发光边框 + 居中大标题 Hero) | 用户明确要求「能真实用起来」。模板味等于没做设计;首页必须是真实内容流,第一屏不能有 Hero |
| **不做「可爱校园 App」感**(草绿 + 圆角卡通插画 + 吉祥物) | 大学生不吃这套,会被判定为低龄化、不严肃。「年轻」靠节奏和文案,不靠插画 |

## 4. 配色系统

### 4.1 设计原则

- 四层配比:中性色 85%-90% / 强调色 5%-8% / 语义色 0%-5% / 效果色 <1%。
- **每屏强调色可见使用 ≤ 2 处**(导航选中态 + 主 CTA)。这一条写进红线。
- 背景刻意是**冷调浅灰 `#F4F6F8`,不是米色/奶油色**。温暖感由强调色、图片和排版承担,不由背景色承担——奶油底是当下最泛滥的 AI 默认背景。
- 所有阴影色相取自 `--ys-fg`(`rgba(16,33,46,*)`),不用纯黑。

### 4.2 主色:友声青 `#0E7490`

取自「嘤其鸣矣,求其友声」——**信号发出去,要有人回应**。青色是这个语义最贴的色相:它是「信号/回应/扩音」的颜色,不是「科技/AI」的颜色。

刻意避开的色值:

| 避开 | 原因 |
|---|---|
| `#6366F1` / `#4F46E5` 靛蓝 | AI 生成物的默认强调色,一眼模板 |
| `#2563EB` 默认蓝 | Tailwind 默认,同样泛滥 |
| `#FF2442` 小红书红 | 直接指向竞品,失去辨识度 |
| 任何紫->粉渐变 | P0 红线 |

**色觉障碍适配**:主色青(蓝黄轴的蓝端)与辅色砖橙(蓝黄轴的另一端)是色觉障碍下辨识度最高的一对。红绿色盲用户对青/橙的区分几乎不受影响。语义色(成功绿 / 警告橙 / 错误红)**一律配图标和文字**,绝不单独靠颜色传达含义(见第 11 节)。

### 4.4 暗色模式:不在 MVP 范围,但结构已预留

**结论:MVP 不做。** 理由:(1) Element Plus 组件的深色需要大量二次覆盖,成本高;(2) 现有 15 个页面没有任何暗色资产(图片、插画、分割线);(3) 校园场景主力使用时段是白天。

**但 Token 架构已按语义命名,Phase 1.5 加 `<html data-theme="dark">` 即可生效。** 深色候选值已实测:底 `#111721`(非纯黑)、正文 `#E6EAF0`(14.89)、辅助 `#8B96A6`(6.00)、元信息 `#7D8798`(4.96)、主色 `#4FD1C5`(9.64)。

## 5. 字体方案

### 5.1 结论:零 Web Font 下载(0 KB)

```css
--ys-font-body: -apple-system, BlinkMacSystemFont, "PingFang SC",
  "HarmonyOS Sans SC", "Microsoft YaHei", "Source Han Sans SC",
  "Noto Sans SC", "Helvetica Neue", Arial, sans-serif;
--ys-font-display: var(--ys-font-body);   /* 标题同栈 */
--ys-font-mono: ui-monospace, SFMono-Regular, "SF Mono", "JetBrains Mono",
  Menlo, Consolas, "Liberation Mono", monospace;
```

### 5.2 为什么不做子集化(这是本节的关键判断)

调研到的硬数据:思源黑体完整包约 8-16MB,阿里巴巴普惠体 3.0 约 8.1MB;即使转 WOFF2 也只能压到 6.8MB 左右,4G 下 8-15 秒。

**子集化对本项目无效。** 子集化的前提是字符集可穷举(品牌名、固定文案、文档站)。友声是 **UGC 产品——用户发什么字无法预知**,任何静态子集都会漏字,漏字会 fallback 到系统字体,出现同一段话里两种字体的「补丁感」,比一开始就用系统字体更糟。

**系统字体栈在三个平台上都是本机最优解**:iOS/macOS 是苹方,Android 是鸿蒙/思源,Windows 是雅黑。零请求、零 FOUT、零 CLS,这与「校园网 2 秒加载」的硬约束一致。

**层级靠字重、字号、字距建立,不靠换字体。** 这是 Linear / Notion 的做法,也是本项目唯一可行的做法。

### 5.3 唯一例外(可选)

Logo / 品牌字「友声」二字若要专属字形,可单独子集化(两个字 + 拉丁,体积 <20KB)。**除此之外不引入任何 Web Font。** 此项为可选,不做也不影响设计完整性。

### 5.4 字号阶梯(8 级)

| Token | 字号 | 行高 | 字距 | 用途 |
|---|---|---|---|---|
| `--ys-text-xs` | 12px | 1.5 | 0.01em | 标签/徽章/计数 |
| `--ys-text-sm` | 13px | 1.6 | 0.01em | 辅助说明/表单 help |
| `--ys-text-base` | **14px** | **1.7** | 0 | **正文基准**(移动与桌面一致)、帖子正文 |
| `--ys-text-md` | 16px | 1.6 | 0 | 卡片标题、会话气泡正文 |
| `--ys-text-lg` | 18px | 1.5 | -0.005em | 分组小标题 |
| `--ys-text-xl` | 20px | 1.4 | -0.01em | 区块标题 |
| `--ys-text-2xl` | 24px | 1.35 | -0.01em | 页面主标题 |
| `--ys-text-3xl` | 30px | 1.25 | -0.015em | 展示级:仅空状态主句/引导页,**不用于首页 Hero** |

正文基准取 14px 而非 15/16px,是因为内容列锁定 640px,14px × 1.7 行高在 640px 下每行约 30-38 个汉字,落在中文舒适阅读区间。

### 5.5 字重与字距

字重三级:**400 正文 / 500 小标题与按钮 / 600 大标题**。

> 标准设计系统常见 510 / 590 两档,但**中文系统字体不提供这两个字重**(苹方/雅黑/思源常规只到 400/500/600/700),强行声明会被浏览器吸附到最接近的字重,造成跨平台不一致。故取 500 / 600。

字距:

| 场景 | 字距 |
|---|---|
| 正文(14-16px) | `0` |
| 小字(12-13px) | `0.01em` |
| ALL CAPS 拉丁标签 | `0.08em`(必须 ≥0.06em) |
| 标题(≥18px) | `-0.01em` |
| 展示字(30px) | `-0.015em`(**中文负字距上限**,再负会挤压字身框,中文比拉丁更敏感) |

数字与时间用 `--ys-font-mono` + `font-variant-numeric: tabular-nums`,防止点赞数/时间跳动。

## 6. 布局系统

### 6.1 断点(mobile-first)

**大学生主力设备是手机,手机不是桌面的降级版本。** 基础样式即手机样式,用 `min-width` 逐级增强。

| Token | 宽度 | 布局策略 |
|---|---|---|
| xs(基础) | < 640px | 单列;顶部精简 header(56px)+ 底部 TabBar(56px);左右留白 16px |
| sm | ≥ 640px | 大屏手机/小平板:卡片网格可双列;留白 16px |
| md | ≥ 768px | 平板:内容列 + 右侧栏移到内容下方;TabBar 仍在底部 |
| lg | ≥ 1024px | 桌面:左侧固定 Sidebar 220px + 内容列 640px + 右侧栏 320px |
| xl | ≥ 1280px | 容器锁定 1180px 居中 |
| 2xl | ≥ 1536px | **不放大内容列**,只增加左右留白 |

### 6.2 栅格与容器

- 栅格:桌面 12 列 / 平板 8 列 / 手机 4 列;gutter 桌面 24px、手机 16px。
- 容器最大宽度 `1180px`;**内容列(正文/Feed)锁定 `640px`**——这是中文阅读舒适宽度的上限,桌面变宽时只增加留白,不拉长行宽。
- 节区垂直节奏:手机 32px / 平板 48px / 桌面 80px。
- 移动端必须处理底部安全区:`padding-bottom: calc(var(--ys-tabbar-h) + var(--ys-safe-bottom))`。

### 6.3 间距(4px 网格)

只允许:`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。
禁止:`5 / 7 / 13 / 15 / 22 / 30` 等非标值。

### 6.4 圆角

| Token | 值 | 用途 |
|---|---|---|
| `--ys-radius-sm` | 4px | 徽章/小标签 |
| `--ys-radius-md` | 6px | chip、小按钮 |
| `--ys-radius-lg` | 8px | 按钮、输入框(默认) |
| `--ys-radius-xl` | **12px** | **卡片(硬上限)** |
| `--ys-radius-2xl` | 16px | 弹窗/抽屉 |
| `--ys-radius-full` | 9999px | 头像、胶囊按钮、Tab 指示器 |

卡片圆角上限 12px。≥24px 的过度圆滑是典型的 AI 味特征。

### 6.5 阴影(三级,禁止发光)

| Token | 值 | 用途 | 约束 |
|---|---|---|---|
| `--ys-shadow-1` | `0 1px 2px rgba(16,33,46,0.05)` | 卡片静止 | 可配 1px 边框 |
| `--ys-shadow-2` | `0 2px 8px rgba(16,33,46,0.08)` | 卡片 hover、顶栏吸顶 | 可配 1px 边框 |
| `--ys-shadow-3` | `0 8px 24px rgba(16,33,46,0.12)` | 浮层:下拉/抽屉/Toast | **禁止配 1px 边框** |

- 模糊半径硬上限 **24px**。
- 禁止 `0 0 Npx` 形式的彩色光晕(发光)。
- 禁止同一元素同时出现 `1px` 边框 + `blur ≥ 16px` 阴影(即「幽灵卡片」)。
- 阴影色相取自 `--ys-fg`,**不用 `rgba(0,0,0,*)`**。

### 6.6 触摸目标

- 最小可点击区域 **44×44px**(WCAG 2.5.5),靠 padding 撑够,不靠放大视觉。
- 相邻可点击元素间距 ≥ 8px。
- 底部 TabBar 单项高度 56px,内部图标 24px + 文字 11px。

## 7. 图标系统

### 7.1 选型结论(附实测依据)

**推荐:`@element-plus/icons-vue@2.3.2`,零新增依赖。**

实测依据(来自本项目 `frontend/node_modules` 与 `package-lock.json`,非推测):

1. `element-plus@2.14.5` 的 **`dependencies` 中直接包含 `@element-plus/icons-vue@^2.3.2`** —— 它是 EP 的硬依赖,**不需要额外安装,也不可能缺失**。
2. 图标库共 **294 个**图标。
3. 图标规格:`viewBox="0 0 1024 1024"` + `fill: currentColor`(填充式描边风格)。
4. 关键:EP 组件内部图标(下拉箭头、清空叉、Message 的成功图标等)全部来自这个库。**用它,产品图标与组件内部图标天然同源,不会出现两套风格混排。**

**被否决的方案:Lucide(`lucide-vue-next`)**。Lucide 是 24×24 + stroke 1.5 的描边风格,语义覆盖更好(有 `megaphone` / `shield` / `thumbs-up` / `pin`),但会带来两个问题:(1) 新增一个运行时依赖;(2) 与 EP 组件内部的 1024 viewBox 填充式图标风格冲突,形成事实上的「两套图标」,违反红线 1。故**不采用**。

### 7.2 EP 图标库缺失的 3 个语义 —— 自绘补齐

实测 EP 2.3.2 **没有** `thumbs-up`、`shield`、`send`(有 `promotion` 喇叭,但已被官方通知占用)。这 3 个由 `src/icons/` 自绘:

| 文件 | 语义 | 是否必须自绘 |
|---|---|---|
| `IconLike.vue` | 点赞:竖起的大拇指轮廓(未赞)/ 实心(已赞) | 是,EP 无 |
| `IconShield.vue` | 管理与审核:盾牌轮廓 | 是,EP 无 |
| `IconSend.vue` | 发送:纸飞机 | 是,EP 无 |

**自绘图标必须与 EP 同为 `viewBox="0 0 1024 1024"` + `fill="currentColor"` 填充风格**,禁止出现 stroke 描边风格。

### 7.3 尺寸与用法

| 场景 | 尺寸 |

| 行内(正文中的小图标) | 16px |
| 按钮内 | 20px |
| 独立图标(导航、空状态、TabBar) | 24px |

只通过 CSS `width/height` 改尺寸,**不改 viewBox**。颜色一律继承 `currentColor`,禁止给图标单独写 `color:`。

## 8. 组件与状态规范

### 8.1 按钮

| 类型 | 底 | 文字 | 圆角 | 内边距 |
|---|---|---|---|---|
| Primary | `--ys-accent` | `--ys-accent-on` | 8px | 10px 16px,最小高 40px(移动端 44px) |
| Secondary | 透明 + 1px `--ys-border-control` | `--ys-fg` | 8px | 同上 |
| Ghost | 透明 | `--ys-accent` | 8px | 同上 |
| Danger | `--ys-danger` | `#FFFFFF` | 8px | 同上 |

### 8.2 输入框

- 默认:底 `--ys-surface`,边框 **1px `--ys-border-control`**(3.16:1,满足 WCAG 1.4.11)。
- focus:边框 `--ys-accent` + `--ys-focus-ring`,**禁止 `outline: none` 而不给替代**。
- error:边框 `--ys-danger` + 下方 13px `--ys-danger` 文字(贴近字段,不汇总到顶部)。
- disabled:底 `--ys-surface-2`,文字 `--ys-meta`。

### 8.3 卡片

- 底 `--ys-surface`,边框 1px `--ys-border`,圆角 12px,阴影 `--ys-shadow-1`。
- hover:边框 `--ys-border-control` + 阴影 `--ys-shadow-2`。**不出现彩色边框、不出现左侧色条、不发光。**

### 8.4 五态覆盖(每个有状态组件必须覆盖)

| 状态 | 要求 |
|---|---|
| **Loading** | 骨架屏(用 `--ys-ease-linear` 的微光扫过),不用全屏 spinner |
| **Empty** | 一句人话 + 一个可点的按钮。**禁止「暂无数据」四个字了事** |
| **Error** | 具体原因 + 重试按钮。写「网络好像断了,点这里重试」,不写「操作异常,请重试」 |
| **Populated** | 正常展示 |
| **Edge** | 超长文本 2 行截断、超长昵称截断、超大数 999+ |

**空状态文案示例**(真实中文,大学生会说的话):

| 场景 | 文案 | 按钮 |
|---|---|---|
| 找搭子无结果 | 这个时段还没人发邀约 | 发个邀约 |
| 陌生人消息为空 | 还没有陌生人找你说话。这样也好 | 去看看找搭子 |
| 通知为空 | 一条通知都没有,清净 | 去首页逛逛 |
| 网络失败 | 网络好像断了,点这里重试 | 重试 |
| 发帖成功 | 发出去了,等别人来搭话吧 | (Toast,自动消失) |

### 8.5 九态矩阵

`default / hover / focus-visible / active / disabled / loading / error / empty / populated` 必须全部覆盖。

## 9. 动效规范

`MOTION_INTENSITY = 3`:只做**传达含义**的动效,不做装饰动画。

| 场景 | 时长 | 缓动 |
|---|---|---|
| 按钮按下、开关切换 | 80ms | `--ys-ease-out` |
| hover 变色、选中态 | **150ms**(收敛值) | `--ys-ease-out` |
| 下拉展开、Toast 进入 | 200ms | `--ys-ease-out` |
| 抽屉滑出 | 280ms | `--ys-ease-in-out` |
| 路由/页面过渡 | **320ms(硬上限)** | `--ys-ease-in-out` |

- 缓动只允许三条:`cubic-bezier(0.2, 0, 0, 1)`(默认)、`cubic-bezier(0.4, 0, 0.2, 1)`(位移)、`linear`(骨架屏)。
- **禁止弹跳/回弹**:禁止 `cubic-bezier(0.68, -0.55, 0.265, 1.55)`,禁止任何控制点 `y < 0` 或 `y > 1`(即禁止 overshoot)。
- 禁止动画 `width` / `height` / `top` / `left`,只动 `transform` 和 `opacity`。
- 禁止同时超过 3 个元素同时动画。
- `prefers-reduced-motion: reduce` 必须全局实现(已在 `design-tokens.css` 内置)。
- 骨架屏微光是唯一允许的 `linear` 循环动画。

## 10. G1 / G2 / G3 页面方案

### 10.1 G1 —— 陌生人破冰私信

**核心设计判断**:破冰的难点不是「能不能发」,是「第一句说什么」。所以**不给空白输入框,给候选话术**。

#### 移动端(<768px)

**入口**:在找搭子条目 / 帖子 / 评论里点用户头像或昵称 -> 底部抽屉(ActionSheet,顶部两角 16px 圆角,从底部升起,280ms)。

**破冰卡结构(从上到下)**:
1. 抓手条(4px × 36px,`--ys-border` 色)—— 明示可下拉关闭
2. 身份区:头像 40px(圆形)+ 昵称(16px/500)+ 「计算机学院 · 大三 · 已认证」(13px `--ys-meta`)
3. 共同点条:`--ys-accent-soft` 底的圆角行,文「你们都在找羽毛球搭子」+ 共同标签 chips
4. 候选话术:3 条,每条是一个整行可点按钮(高 44px,1px `--ys-border` 底,圆角 8px)。话术由共同标签 + 来源上下文生成,例如:
   - 「同学你好,看到你也想找人打羽毛球,周末三号场有人吗?」
   - 「我也在找搭子,你一般什么时候有空?」
   - 「三号场我订过,要不要一起?」
5. 第 4 行:「自己写一句」(展开输入框)
6. 底部固定:主按钮「发送这句」(`--ys-accent` 实底,铺满宽,高 44px)+ 次要文字按钮「先看看 Ta 的主页」

**键盘弹起时**:话术区压缩为横向滚动条(高 44px),输入框贴在键盘上方,主按钮上移。

**发送后**:进入会话页。会话顶部有一条**来源上下文条**(`--ys-surface-2` 底,12px 高 32px):图钉图标 + 「来自:周五三号场羽毛球」+ 右侧关闭叉。这条上下文是对话的「由头」,让对方知道你是谁、为什么找他——**这是「不加好友也能聊」能成立的关键**。

**防骚扰机制(写进交互,不写进弹窗报错)**:
- 陌生人首条消息每天 3 次配额。
- 配额用尽:主按钮变为 disabled,按钮下方一行 13px `--ys-meta` 文字「今天打招呼的次数用完了,明天再来」。**不弹错误弹窗。**
- 接收端:陌生人消息进入「陌生人消息」折叠分组,默认收起,需一次点击展开;分组头有「3 条未读」和一键「全部忽略」。

#### 桌面端(≥1024px)

- 点头像 -> **居中 Modal 480px**(不是抽屉,桌面用抽屉会让人以为是系统面板)。两栏:左 40% 显示来源上下文卡(来源帖子摘要 / 共同标签),右 60% 是话术列表 + 输入框。
- 会话页:左侧会话列表 320px(含「陌生人消息」折叠分组)+ 右侧会话区。

#### 状态覆盖

- Loading:打开抽屉先显示身份区骨架屏(头像圆 + 两行文字条)
- Empty:无任何共同标签时,第 3 区改为「你们还没有共同标签」+ 一条通用话术「同学你好,在友声看到你,想认识一下」

### 10.2 G2 —— 找搭子(按兴趣标签发现同学)

**核心设计判断(来自竞品调研)**:列表单元是**一个具体的邀约**,不是一个人。人的属性和兴趣已经体现在那句邀约里了。

#### 移动端(<768px)

**顶部粘性筛选条**(高 48px,`--ys-surface` 底,吸顶,下方 1px `--ys-border`):
- 4 个大类 chip 横向滚动:运动 / 游戏 / 学习 / 社团。chip = 各自类目浅底 + 深字,圆角 `--ys-radius-full`,高 32px,可多选。选中态:底 `--ys-accent-soft` + 文字 `--ys-accent` + 边框 1px `--ys-accent`。
- 右侧「筛选」漏斗图标(44×44):时间(今晚 / 周末 / 不限)+ 校区。

**邀约清单**(单列,条目间 `border-top: 1px solid var(--ys-border-soft)`,**无卡片盒子**):

每条结构(左右布局):
- 左:头像 36px(圆形)
- 中(主区):
  - 第 1 行(13px `--ys-meta`):昵称 · 计算机学院 · 20 分钟前
  - **第 2 行(16px / 500 / `--ys-fg`,最多 2 行)**:「周五下午三点三号场,缺两个人,来吗」← **这是主信息**
  - 第 3 行:标签 chips(运动 / 羽毛球 / 三号场)+ 时间 + 地点(时钟 + 定位标记 + 13px `--ys-meta`)
- 右:胶囊按钮「打招呼」(`--ys-accent` 描边 + `--ys-accent` 文字,高 44px,最小宽 72px)

**已打招呼的条目**:右上角 12px `--ys-meta` 文字「已打招呼」,按钮文案变「再聊一句」。

**空状态**:居中,30px/600 主句「这个时段还没人发邀约」+ 13px 副句「换个时间,或者自己发一个」+ 主按钮「发个邀约」。

#### 桌面端(≥1024px)

- 左列 220px 侧栏(Sidebar)承载导航;**筛选条移到内容列顶部**(sticky,高 56px)。
- 内容列 640px 居中,条目结构与移动端一致,但左右留白 24px,条目 hover:底色 `--ys-surface-2`,右侧操作区浮现。
- 右侧 320px 栏:「我可能感兴趣的圈子 / 近期活动」(`--ys-surface` 卡片,圆角 12px)。

#### 状态覆盖

- Loading:6 条骨架条目(头像圆 + 三行文字条,`linear` 微光)
- Empty:见上
- Error:整列表替换为「没加载出来,点这里重试」+ 重试按钮
- Edge:邀约句 2 行截断(超出显示「…全文」);标签超过 4 个折叠为「+2」

### 10.3 G3 —— 官方通知(学校/学院公告一站触达、置顶)

**核心设计判断**:官方通知的权威感靠**深墨徽章 + 来源署名**,不靠彩色边框,也不消耗主色预算。

#### 首页公告条(一级入口,移动端与桌面端都有)

- 位置:顶部 header 之下,Feed 之上的第一个区块。
- 最多显示 **2 条**未读官方通知(按置顶 > 时间排序),第 3 条起折叠为「查看全部 5 条」。
- 每条:底 `--ys-official-surface`,圆角 12px,内边距 12px 16px。
  - 左:深墨徽章 chip(`#16212E` 底 + 白字,11px,圆角 4px,文字为来源机构名如「教务处」)
  - 中:标题 14px/500,1 行截断
  - 右:图钉图标(已置顶时)+ 右上角关闭叉(收起,当天不再出现)
- 点击整条 -> 进详情。
- 置顶 24 小时后自动降为普通通知(徽章下方的「置顶」标记消失)。

#### 通知页(/notify)

**顶部 Tab 3 个**:全部 / 官方 / 互动。官方 Tab 有未读计数红点(红点用 `--ys-danger` 实心 6px 圆 + `aria-label`)。

**官方条目**(视觉上与普通条目明确区分,但不靠彩色边框):
- 整行底色 `--ys-official-surface`(比互动条目的 `--ys-surface` 深一档)
- 左侧来源徽章(深墨底白字,机构名)
- 标题 14px/600
- 摘要 2 行,13px `--ys-muted`
- 底部 meta 行(12px):时间 + 图钉图标 + 「置顶」文字 + 回形针图标 + 附件数
- **置顶分组**:官方 Tab 内最上方独立分组,最多 3 条,分组头「置顶」+ 图钉图标;管理员可见每条右侧的「取消置顶」文字按钮

**关键交互**:
- 官方通知**保留 30 天**,不随「已读」消失(互动通知已读后从列表移除)。
- **不提供「一键全部已读」的一次性误触** —— 官方通知的批量已读需二次确认。
- 置顶权限仅管理员;置顶上限 3 条,超过时提示「置顶位满了,先取消一条」。

#### 移动端

- 单列列表,点击整条 -> 跳转详情页(不展开)。
- 详情页顶部:来源机构名 + 发布日期 + 正文(16px / 1.7)+ 附件列表(回形针 + 文件名 + 大小)。

#### 桌面端(≥1024px)

- **两栏,不跳页**:左 360px 通知列表 + 右侧详情预览区。点击左侧条目,右侧直接展开正文。
- 选中态:条目底色 `--ys-accent-soft` + 标题色 `--ys-accent`。**不用左侧色条**(彩色侧边框是红线)。

#### 状态覆盖

- Loading:列表骨架屏
- Empty(官方为空):「还没有官方通知。有新的会第一时间出现在这里」
- Error:「没加载出来,点这里重试」
- Edge:标题 1 行截断;机构名超长截断;附件名超长中间省略

## 11. 无障碍要求

| 项 | 要求 |
|---|---|
| **对比度** | 正文与背景 ≥ 4.5:1(已全部实测,见第 4.3 节表);大号文本 ≥ 3:1;控件边界 ≥ 3:1(`--ys-border-control` = 3.16) |
| **键盘可达** | 所有交互元素可 Tab 到达、可 Enter/Space 激活、可 Esc 关闭浮层;Modal/抽屉做焦点陷阱与关闭后焦点归还 |
| **焦点可见** | 统一 `:focus-visible { box-shadow: var(--ys-focus-ring) }`。**禁止 `outline: none` 而不给替代** |
| **触摸目标** | 最小 44×44px;相邻可点元素间距 ≥ 8px;TabBar 项 56px |
| **屏幕阅读器** | 纯图标按钮必须有 `aria-label`(例:通知铃铛写 `aria-label="通知,3 条未读"`);图片必须有 `alt`;官方通知到达用 `role="status"` 播报;Tab 用 `role="tab"` + `aria-selected` |
| **不靠颜色单独传达信息** | 置顶 = 图钉图标 + 「置顶」文字(不只是颜色);未读 = 实心圆点 + `aria-label`;错误 = 图标 + 文字(不只是红边框) |
| **语义化** | 用 `<button>` 而非 `<div @click>`;列表用 `<ul>/<li>`;导航用 `<nav>` |
| **表单** | 可见 label,**不用 placeholder 当 label**;错误提示贴近字段,不汇总到顶部;必填项同时有 `required` 与视觉标记 |
| **减弱动效** | `prefers-reduced-motion: reduce` 全局实现(已在 CSS 内置) |
| **中文排版** | 内容列 640px,正文 14px/1.7,每行 30-38 汉字;行高不低于 1.5 |

## 12. 五条设计红线(唯一强制项)

> 以下每条都配了可自动检查的判定方式。团队任何人写 UI 都不得违反。

### 红线 1:图标唯一来源,零 emoji

- 产品 UI 图标**只允许来自 `@element-plus/icons-vue@2.3.2`**;缺失的 3 个语义(点赞拇指 / 盾牌 / 发送纸飞机)由 `src/icons/` 自绘补齐,**必须为 `viewBox="0 0 1024 1024"` + `fill="currentColor"` 填充风格**,禁止 stroke 描边风格混入。
- 尺寸只有三档:行内 16px / 按钮内 20px / 独立 24px。只改 CSS `width/height`,不改 viewBox。
- 图标颜色一律 `currentColor`,禁止单独写 `color:`。
- **禁止任何 emoji 作为功能图标。**
- 检查方式:`rg -n "[\x{1F300}-\x{1F9FF}\x{2600}-\x{26FF}\x{2700}-\x{27BF}]" frontend/src/` 必须零命中;`rg -n "lucide|<svg[^>]*stroke-width" frontend/src/` 只允许命中 `src/icons/` 之外零处。

### 红线 2:零硬编码颜色

- 业务代码禁止出现硬编码色值。唯一例外:`#fff` / `#ffffff` / `#000` / `#000000`。
- 所有颜色必须走 `var(--ys-*)`。Element Plus 组件**不要直接改 `--el-*`**,改 `design-tokens.css` 的 Bridge 段。
- 禁止 `rgba(0, 0, 0, *)` 作为阴影色,用 `rgba(16, 33, 46, *)`。
- 检查方式:`rg -n "#[0-9a-fA-F]{3,8}" frontend/src/` 的命中项,除白名单外必须为零;命中即失败。

### 红线 3:阴影与边框克制

- `box-shadow` 模糊半径不得 > 24px。
- **同一元素不得同时存在 `border: 1px solid` 与 `box-shadow` 模糊半径 ≥ 16px**(幽灵卡片)。
- 禁止发光:`0 0 Npx` 形式的彩色扩散光晕。
- 禁止卡片/列表项使用 `border-left-width` 或 `border-right-width` > 1px 的彩色边框(侧条纹)。
- 检查方式:人工走查 + `rg -n "box-shadow" frontend/src/` 检查模糊值;`rg -n "border-left|border-right" frontend/src/` 检查宽度 ≤ 1px。

### 红线 4:强调色预算与渐变禁令

- 单个视口内 `--ys-accent` 可见使用 **≤ 2 处**(导航选中态 + 主 CTA)。
- `--ys-accent-2`(砖橙)**仅允许**出现在「活动 / 搭子」标签与入口,禁止用于主 CTA。
- **禁止渐变文字**(`background-clip: text` + 渐变背景)。
- **禁止紫->粉渐变**:`#7C3AED` / `#A855F7` / `#9333EA` / `#EC4899` 四个色值一律禁止出现,且禁止与 `linear-gradient` 同现。
- 紫色 `#6B3FA0` **仅允许**作为「游戏」兴趣标签的文字/浅底出现,禁止进入主视觉、按钮、背景、渐变。
- 检查方式:`rg -n "7C3AED|A855F7|9333EA|EC4899" frontend/src/ docs/` 必须零命中;`rg -n "linear-gradient" frontend/src/` 命中项需逐条人工确认非紫粉、非渐变文字。

### 红线 5:动效与文案

**动效**:
- 所有 `transition-duration` / `animation-duration` ≤ 320ms。
- 缓动只允许 `var(--ys-ease-out)` / `var(--ys-ease-in-out)` / `linear`。
- **禁止弹跳**:禁止 `cubic-bezier(0.68, -0.55, 0.265, 1.55)`,禁止任何控制点 `y < 0` 或 `y > 1`(禁止 overshoot)。
- 禁止动画 `width` / `height` / `top` / `left`,只动 `transform` 与 `opacity`。
- 必须实现 `@media (prefers-reduced-motion: reduce)`。
- 检查方式:`rg -n "cubic-bezier" frontend/src/` 命中项的控制点 y 值必须在 [0, 1];`rg -n "duration|animation-duration" frontend/src/` 值 ≤ 320ms。

**文案**:
- 界面文案禁止出现「Welcome to」「Lorem ipsum」「Sign up today」「敬请期待」「暂无数据」等无信息量占位。
- **每个空状态必须给出「一句人话 + 一个可点的按钮」**,文案必须是大学生真实会说的话。
- 错误提示必须说明具体原因与下一步动作(「网络好像断了,点这里重试」),禁止「操作异常,请重试」。
- 检查方式:人工走查所有空状态与错误态。

## 13. Element Plus 落地指南(给前端)

### 13.1 Token 接入顺序(不可调换)

```js
// main.js
import 'element-plus/dist/index.css'   // 先
import './styles/design-tokens.css'    // 后(本文件覆盖 --el-*)
```

把 `docs/design/design-tokens.css` 复制到 `frontend/src/styles/design-tokens.css` 并替换现有 `tokens.css` 的引入。

### 13.2 已发现的现存违规(必须修)

现有 `frontend/src/styles/tokens.css` 中有两处与红线冲突:

1. `.el-card:hover { box-shadow: 0 4px 16px rgba(0, 0, 0, 0.06); }` —— 模糊半径 16px,而 `.el-card` 同时有 `1px` 边框 -> **命中红线 3「幽灵卡片」**。改为 `--ys-shadow-2`(`0 2px 8px rgba(16,33,46,0.08)`)。
2. 阴影用 `rgba(0, 0, 0, *)` 纯黑 -> **命中红线 2**。改为 `rgba(16, 33, 46, *)`。
3. 字体栈缺 `"HarmonyOS Sans SC"`,安卓鸿蒙机型会 fallback 到思源,建议补齐。
4. 旧的 `--app-bg` / `--card-radius` 等自定义变量应迁移到 `--ys-*` 命名空间,避免两套变量并存。

### 13.3 图标裁决(请求架构师最终确认)

我的推荐是 **沿用 `@element-plus/icons-vue`,不引入 Lucide**,依据是实测:它是 `element-plus@2.14.5` 的 `dependencies` 直接依赖,零新增安装;294 个图标;与 EP 组件内部图标同源。

**但请注意**:`package.json` 的 `dependencies` 中**并未显式声明** `@element-plus/icons-vue`(它靠 element-plus 的依赖传递进来)。建议架构师在 Spec 中显式锁定版本 `"@element-plus/icons-vue": "^2.3.2"`,避免未来 EP 升级导致图标包版本漂移。

### 13.4 EP 组件覆盖注意点

- `el-card` 圆角会被 Bridge 的 `--el-border-radius-round` 影响,卡片统一用 `.ys-card` 类或覆盖 `--el-card-border-radius`。
- `el-button` 的主色由 `--el-color-primary` 驱动,已 Bridge 到 `--ys-accent`,无需逐个改。
- `el-tag` 的兴趣标签需自定义 class 使用 `--ys-cat-*` 颜色,不要用 EP 的 `type="success"` 等(语义色与兴趣类别是两套东西)。
- `el-message` / `el-notification` 的图标来自 EP 图标库,会自动跟随主色,不需要处理。
- EP 默认过渡时长已在 Bridge 中收敛到 150ms / 80ms。

### 13.5 性能预算(与设计相关)

| 项 | 预算 |
|---|---|
| Web 字体 | **0 KB**(系统字体栈,见第 5 节) |
| 图标 | 按需引入 EP 图标组件,tree-shaking 后单页通常 < 5 KB |
| 首屏图片 | 帖子图片懒加载 + 响应式 srcset,首屏不超过 3 张 |
| 目标 LCP | 校园网 4G 下 < 2.0s(与竞品调研的校园场景硬约束一致) |

### 14.3 我认为这个项目最容易踩的设计坑

**把「找搭子」做成「另一个陌陌」。**

具体表现:列表单元设计成「头像 + 昵称 + 年龄 + 兴趣标签 + 打招呼按钮」,也就是**以「人」为单位**。这会让产品立刻滑向颜值社交的语义,女生用户体验迅速恶化,官方通知的权威感也会被稀释——最终「校园」这个限定词失去意义,产品退化成又一个陌生人社交 App。

竞品调研给出的正确答案是反直觉的:**以「具体邀约」为单位**。列表里最显眼的那一行不是「李同学,男,大三」,而是「周五下午三点三号场,缺两个人,来吗」。头像缩小到 36px,昵称降到 13px,那句邀约句用 16px。

这个差别看起来只是排版权重,实际决定了产品的语义:**你是在挑一个人,还是在应一个局。** 大学生真实社交是后者。

1信息顺序：发布者上前、警告让位

现在的顺序把「谁发的」放在很后面，用户读完信息才看到人；而大段免责声明横在中间，把正文和留言隔开。

现在

  1. 分类 · 王者荣耀 · 倒计时
  2. 标题「今晚开黑缺一个打野」
  3. 正文「晚上八点，钻石以上」
  4. 信息卡（地点/价格/人数/剩余）
  5. 免责声明（大段文字，占 4 行）
  6. 发布者（头像 + 昵称 + 时间）
  7. 分割线
  8. 留言区（提示 + 警示 + 输入框 + 列表）

改后

  1. 发布者（头像 + 昵称 + 时间）← 提到最上
  2. 分类 · 王者荣耀 · 倒计时
  3. 标题「今晚开黑缺一个打野」
  4. 正文「晚上八点，钻石以上」
  5. 信息卡（地点/价格/人数/剩余）
  6. 留言区 ← 紧接信息卡
  7. 免责声明（改成首次弹窗）
  8. 分割线（不再需要）
✓
发布者提到最上：集市是「找一个人办事」的场景 —— 用户第二个想知道的就是「这人靠谱吗」。现在它被 4 行免责声明隔在很后面，等于把最重要的信任信号藏了。
✗
免责声明挤出正文区：它占 4 行、颜色又比正文还重（暖底块），读者会以为它才是正文。这类「每次都要看的免责」适合做成一次性提示，而不是常驻。

为什么这么改
问题说明
占屏 常驻 textarea 至少 90px 高（含边框与按钮），而多数访客只看不留言 —— 这块空间对他们是纯浪费。
键盘遮挡 手机点进 textarea 后键盘弹起，页面会被顶起，而输入框可能正好在键盘下方 —— 现在已经要额外处理。
误触 滚动时手指容易碰到 textarea，直接弹键盘打断浏览。
抽屉优势 抽屉是主动发起的，键盘弹起时抽屉跟着上移，输入区天然在可视区顶部；关闭后页面回到原位。
桌面端不改成抽屉。桌面没有键盘遮挡问题，常驻输入框更顺手（可以边读留言边写）。保留现在的做法，只在 <1024px 用按钮 + 抽屉。
列表页不放输入框。详情页「留言 N 条」下面直接是列表，每条只显示「昵称 / 内容 / 时间 / 举报」。写留言统一从右上角「写留言」进 —— 一个入口，不散落。
1
入口在留言区标题右侧：留言 3 条 ······ [写留言]。位置固定，不随列表长度变化。
2
抽屉里的结构：标题 + 关闭、textarea（自动聚焦）、字数 0/500、主按钮「发出去」、一行隐私提示。隐私提示只在写留言时出现，读完就收。
3
空态：还没有留言时，标题下方显示「还没有留言 · 来做第一个」，右侧按钮变成「写第一条」。空态也提供入口，不只依赖右上角。
4
草稿保留：抽屉意外关闭（点遮罩/按 ESC）时保留草稿，下次打开还在。现有的 submitError 保留草稿逻辑可以复用。

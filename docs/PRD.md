## 0. 一句话定位

**友声是一个"校内实名背书、不用加好友就能搭话"的校园生活社区。**

拆开三个关键词：

- **校内实名背书**：用学号/校园邮箱证明"你是这个学校的人"，把校园墙的野生匿名环境换成可追责的校内身份。
- **不用加好友就能搭话**：这是微信明确拒绝做、QQ 群也做不好的事，是本产品的第一差异化。
- **校园生活社区**：不是课程表工具，不是陌生人交友，是"找到同校能一起玩的人"。

## 1. 问题陈述

### 1.1 用户原话（未粉饰）

> "大学同学之间沟通不方便，信息获取不方便。发个东西要靠校园墙转发，想找人玩还得加微信好友/QQ好友才能聊天。"
>
> "微信很专业用户广，但必须先加好友——一对一加、群里加、朋友推荐加，很不友好。"

### 1.2 三个具体的"现在怎么解决的，为什么不行"

**场景 A：想找人打游戏，必须先把对方变成好友**

大二学生想找人开黑，流程是：在群里喊 -> 有人应 -> 加 QQ/微信 -> 打一局 -> 这个人永久躺在通讯录里。
不行的地方：**一次性的需求，被强制变成永久关系。**
这不是个别感受。2026 年 7 月 `#微信能不能出一个临时好友功能#` 话题冲上微博热搜第一，上万名网友集体呼吁；微信官方最终明确答复"暂不推出临时好友功能"，理由是不希望放开陌生人直接私聊通道。国民级产品已经用"明确拒绝"为这个需求做了背书——需求真实，但供给方不提供。

**场景 B：校园通知在群里被聊天淹没，看了又看不见**

辅导员的公开吐槽：刚发完的通知，不到一小时就有同学来问"老师，啥事儿呀"。学生的真实困境是群太多——班级群、年级群、专业群、社团群、课程群，少则十几个多则几十个；为了不被轰炸开了免打扰，结果 @全体成员 的重要通知也一起被屏蔽，错过了奖助学金报名、缓考申请截止、体检时间调整。
不行的地方：**QQ/微信群是"时间序"的，重要信息和闲聊在同一个流里竞争注意力，且平台无法区分。**

**场景 C：想发个东西，只能求校园墙转发**

87.12% 的受访大学生使用过"校园墙"。但满意度只有 67 分，40% 的人打 60 分以下；主要抱怨是广告营销过多（40.14%）、兼职诈骗（35.02%）、虚假信息（32.91%）、重复刷屏（25.54%）、语言暴力（24.07%）、隐私泄露（22.28%）。
不行的地方：校园墙是**投稿制 + 学生自发运营**，没有筛选机制（运营者原话："学生们怎么发的，我们就怎么发出去"），且**绝大多数未获学校授权**——2024 年江西财经职业学院、2026 年河北对外经贸职业学院等校已公开发声明严打非官方校园墙。

### 1.3 一句话总结痛点

大学生在校内想做三件事——**找到人、说上话、不错过通知**——目前分别要靠"加好友（永久关系绑架）"、"群聊（时间序淹没）"、"校园墙（无审核无授权）"三个都明显不趁手的工具完成。这三件事本该由同一个校内社区承接。

## 2. 目标用户

### 2.1 主要画像 P1：林小满，大二，计算机学院

| 维度 | 内容 |
|---|---|
| 年级/专业 | 大二，计算机科学与技术，本校第 2 年 |

| 核心动机 | 想找同校的人一起打游戏（王者/金铲铲）、一起吃饭、偶尔一起打球。不想加一堆不熟的人当好友 |

| 会为什么而走 | 连续 3 次搭话没人回；或者收到 2 条广告/诈骗私信 |

### 2.2 主要画像 P2：陈嘉树，大一新生，外国语学院

| 维度 | 内容 |
|---|---|

| 手机现状 | 开学被拉进 12 个群（班级、年级、宿舍、社团、专业课），全部免打扰 |

| 为什么留下来 | 有人把官方通知可靠地推给他，且不用在 999+ 里捞 |
| 会为什么而走 | 通知延迟、或者又要加群才能看 |

### 2.3 次要画像 P3：周学姐，大三，社团负责人（信息发布方 / B 侧）

| 维度 | 内容 |
|---|---|
| 身份 | 校动漫社社长，负责通知 180 名社员 |
| 痛点 | 群里发通知没人看，活动当天来 12 个人；反复催，自己累，社员烦 |
| 核心诉求 | **"我想知道谁还没看。"** 这是她愿意换平台的唯一理由 |
| 为什么留下来 | 能看到已读/未读名单，未读的一键提醒 |
| 价值 | 她是冷启动的关键杠杆——1 个社长 = 180 个被动注册用户 |

### 2.4 明确不是我们的用户

- 已毕业校友（本轮不做跨校与校友关系链）
- 高中生、考研机构、校外商家
- 想在本校做广告投放的商家（本轮无商业化）

### 3.2 替代方案（用户现在实际在用什么）

| 替代方案 | 用户为什么用它 | 为什么"不是最便捷"（用户原话） |
|---|---|---|
| **QQ 群 / 微信群（班级群、社团群）** | 零成本、全员都在、无需下载 | 群太多分不清（十几到几十个）；通知被闲聊淹没；开免打扰就错过重要通知，不开就被轰炸；**想聊天必须先加好友** |
| **钉钉 / 企业微信 / 学校教务系统** | 官方权威，通知有据可查 | 是"办公工具"不是"生活社区"，学生不会为社交打开它；界面陈旧，日活极低（"官方门户 UI/UX 差，学生很少每天登录查看"） |
| **校园墙本身** | 无需加好友就能触达全校，匿名无压力 | 必须求运营者代发，时效性取决于运营者是否在线；内容无筛选；无授权有法律风险 |
| **社团/线下招新 + 通讯录** | 面对面建立信任 | 覆盖面窄，只覆盖到社团成员；线下时间成本高 |

### 3.3 差评里挖出的市场空白（最关键发现）

把三组差评放在一起看，结论非常清晰：

1. **微信明确拒绝"临时好友"** -> "不加好友也能说话"是被国民级产品验证过、但**拒绝供给**的需求。
2. **校园墙 87.12% 渗透 + 40% 不满意 + 学校官方在封杀** -> 校园信息的需求真实存在，但当前供给是**无审核、无授权、不可持续**的野生形态。
3. **Fizz 因匿名在海外高校被封禁、即刻因"兴趣无法通向人"而流失用户** -> 两条已被验证的死路：**完全匿名** 和 **只做内容不做关系**。

> **市场空白 = 一个有校内身份背书（不像校园墙野生）、有审核（不像 Fizz 失控）、能让人不用加好友就搭上话（不像微信）、且兴趣能直接通向人（不像即刻）的校园社区。**
>
> 这正是友声的定位。四条边，缺一条都不成立。

## 4. 我们的差异化

| 差异化点 | 用户能感知到的具体表达 | 竞品做不到 / 不愿做的原因 |
|---|---|---|
| **校内实名，对外昵称** | "你能看到对方是真的本校学生，但看不到他真名" | 校园墙无验证能力；Fizz 只验证邮箱不验证人；Soul 完全去身份 |
| **搭话不用加好友** | "看到一个人，点一下就能说句话，对方不理你也不会尴尬" | 微信明确拒绝做临时好友；QQ 群必须加好友私聊 |
| **公告不被免打扰吃掉，且要求已读回执** | "学院发的通知一定会弹给你，看没看辅导员看得到" | QQ/微信群无法分级；教务系统学生不打开 |
| **有审核、有举报、有处理时限** | "发广告和诈骗的会被处理，不是没人管" | 校园墙是学生自组织，"没有过滤机制"；Fizz 的学生志愿者审核明显不足 |
| **兴趣标签直接通向人** | "选了'王者荣耀'标签，就能看到同校同样选了它的人，直接搭话" | 即刻的问题正是"兴趣无法通向人" |

**用户为什么选我们而不是竞品**：因为友声是唯一一个"在校园这个半熟人场域里，既保证对方真实可追责，又不需要用永久好友关系换一次对话"的地方。半熟人场域是微信做不了、Soul 不愿做、校园墙做不到的交叉地带。

### 5.1 三大缺口的验证结论

我对 G1 / G2 / G3 做了逐一核验，**三个缺口全部成立**，且 G2 比预判更严重。

**G1 陌生人破冰 —— 成立（严重）**

`Relation` 表字段：`id, fromUserId, toUserId, type, createTime, updateTime, isDeleted`。
只有 `type` 一个整型区分关系，实装为关注 / 好友 / 黑名单。**没有任何"未建立关系也能发起对话"的通道**——`ChatConversation` 只在关系成立后才可用。
结论：用户说的"想找人玩还得加微信好友才能聊天"，在友声现有代码里**同样是断的**。这不是竞品的缺点，这是友声自己的缺点。

**G2 找搭子 / 兴趣匹配 —— 成立（比预判更严重）**

- `User` 表字段：`username, passwordHash, studentNo, nickname, avatarUrl, grade, dept, status, role, followerCount, followingCount, unreadNotifyCount`。**没有任何兴趣标签字段，没有 gameTags / hobbyTags，甚至没有 schoolId 字段**（只有 `grade` 年级 和 `dept` 院系两个字符串）。
- `Circle` 表字段：`id, name, ownerId, memberCount, status`。**没有分类标签、没有学校字段、没有简介**。
- `Activity` 表字段：`title, circleId, capacity, currentCount, startTime, endTime, status`。**没有地点、没有标签、没有"缺几个人"**。

结论：当前 Circle 是一个"只有名字的群"，没有可检索的维度。用户"按兴趣标签找人一起打游戏"这个诉求，在现有数据结构下**根本无法实现**——不是效率不足，是能力缺失。需要数据模型变更（这是本轮最大的改造项）。

**G3 官方通知一站触达 —— 成立**

`Notify` 表字段：`id, userId, type, targetId, postId, actorId, isRead`。
`type` 是社交事件类型（点赞 / 评论 / 关注），`actorId` 是触发者。
结论：**没有发布主体（学校/学院/社团）维度、没有置顶字段、没有已读回执字段、没有"公告"这一信息类型**。与社交互动通知混在同一张表同一条流里，会重演 QQ 群"重要通知被闲聊淹没"的失败。

## 6. 功能模块清单与 RICE 评分

### 6.1 评分口径与假设依据

**Reach（1-10，每季度受影响用户比例）** 以单校首年目标 5000 注册 / 1500 MAU 为分母：
- 10 = 全部注册用户都会经过（注册、登录、移动端浏览）
- 8-9 = 80%-90%
- 6-7 = 60%-70%（有明确兴趣的活跃层）
- 4-5 = 40%-50%
- 1-3 = 少数角色

**Impact（0.25 / 0.5 / 1 / 2 / 3）**：
- 3 = 巨大（直接决定"能不能找到人玩"这个第一诉求）
- 2 = 高（决定"会不会错过事"和"敢不敢用"）
- 1 = 中（体验优化）
- 0.5 / 0.25 = 微小

**Confidence（50% / 80% / 100%）**：
- 100% = 有工程事实或权威数据支撑
- 80% = 有竞品差评/热搜等强外部信号，但无本项目自身数据
- 50% = 凭判断

**Effort（1-10，人月折算）**：本轮由 1 名 Java 开发者执行，按实际人日折算：
- 1 = 1-3 人日 · 2 = 4-7 人日 · 3 = 1.5-2 人周 · 4 = 3-4 人周 · 6 = 5-6 人周 · 8 = 2 个月以上

### 6.4 MVP 范围（RICE Top，仅 5 项）

严格按规则，MVP 只保留评分最高且互相咬合的项。本轮 MVP = **F1 + F2 + F3 + F5 + F11**，理由如下：

- **F1（移动端优先）** 是形态前提。用户明确"先做网页"，但大学生不使用桌面网页，不做移动适配等于没做。
- **F2（校内身份）** 是差异化地基。没有它，友声只是又一个校园墙。
- **F3（免好友搭话）** 是第一诉求解法，也是用户原话的直接回应。
- **F5（官方公告）** 是唯一能带来"被动批量注册"的功能（B 侧驱动 C 侧），也是冷启动杠杆。
- **F11（引导与种子内容）** 决定新用户第一次打开看到的是不是一个空壳。空 Feed 是社区产品最常见的首日流失原因。

F6 / F7 / F9（兴趣标签与找搭子）列为 **MVP+**，即 MVP 上线后紧接着的第二批，**不进首版**。理由：它们需要 User / Circle / Activity 三张表的数据模型变更，是本轮最大改造项，且与 F3 存在依赖（找搭子的终点是搭话，搭话不先做好，找搭子就是空转）。

**F4（内容安全闭环）不列入 MVP 但必须同期完成**——它不产生新功能价值，但一旦缺失会导致上线即出事。作为"上线门槛项"处理，不占用 MVP 功能排序。

## 7. 核心功能详细定义

所有图标需求一律由统一 SVG 图标库提供（具体选型由架构师按项目锁定），本文档只用文字描述图标语义，不使用任何 emoji。

### F1 移动端优先响应式改造

- 视口断点：手机（<640px）为**默认设计基准**，平板（640-1024px）、桌面（>1024px）为适配。
- 底部主导航栏固定 5 个入口（首页 Feed 图标、圈子图标、发布图标、消息图标、我的图标），桌面端改为左侧栏。
- Feed 卡片单列全宽，图片懒加载 + 渐显，骨架屏占位。
- 所有表单（登录/注册/发布）输入区高度 ≥ 44px 触控热区。
- 禁止在移动端出现横向滚动。

### F2 校内身份归属与认证

- 注册后强制补充：学校、学院/系、入学年级。（现有 `User` 已有 `grade` / `dept`，需补学校字段与结构化改造）
- 认证方式二选一（用户可跳过，但未认证用户有明确限制）：
  - **学号 + 姓名后两位** 校验（需学校教务数据或院内白名单，冷启动阶段用人工核验兜底）
  - **校园邮箱验证码**（`@xxx.edu.cn` 域名校验）
- 认证成功后主页展示"已认证 · XX 大学"标识（盾牌图标 + 文字），未认证展示"未认证"灰色标识。
- **认证 ≠ 实名展示**：对外一律显示昵称 + 头像，认证状态只展示"是否本校"，不展示真实姓名、学号。
- 未认证用户的限制：不能发布公告、不能发起搭话（防校外骚扰）、发布的帖子标注"未认证"。

### F3 免好友"搭话"（本轮第一差异化功能）

**产品形态：递一张纸条，不是发好友申请。**

1. **入口**：在个人主页、Feed 卡片作者区、圈子成员列表、搭子帖参与者列表上，均有一个「搭句话」按钮（对话气泡图标）。注意措辞是"搭句话"，不是"加好友"。
2. **搭话卡**：点击后弹出一张卡片，包含三部分：
   - 一句话输入框（限 50 字，必填）
   - **共同话题锚点**（自动带出，不可编辑，至少显示一个）：

     - 同在「XX 圈子」
     - 同玩「XX」标签
     - 同为「XX 学院 20XX 级」
     - 你们有 N 个共同关注
   - 发送按钮

   **锚点必须具体到能当话题用。** "你们都在同一个学校"这种锚点不允许出现——它不构成开口理由。
3. **对方收到什么**：一个「待回应」的纸条，出现在消息页顶部的独立分组，带倒计时（24 小时）。
   - 对方回复任意一句话 -> 双方建立正式会话，纸条转为普通会话。
   - 对方 24 小时未回 -> 纸条自动消失，**发送方不会收到"对方已拒绝"这类提示**，纸条静默归档。
   - 对方点「不感兴趣」 -> 纸条立即消失，且 7 天内不再收到此人搭话。
4. **护栏（三条，缺一不可）**：
   - 每人每日搭话上限 5 次（防骚扰，冷启动期可调）
   - 搭话内容经过敏词 DFA 过滤（已有能力）+ 接收方可一键举报
   - 连续被 3 个不同用户标记"不感兴趣" -> 该用户当日搭话功能暂停，需完成一次安全提示后恢复
5. **核心设计原则**：**"不回"必须是零成本的、静默的。** 这是解决微信"加了好友不好意思删"痛点的关键——不回不产生任何社交负债。

### F5 官方公告通道

**产品定位：公告不是通知的一种，公告是另一类信息。**

1. **独立信息类型**：公告与点赞/评论/关注通知在数据结构与展示上完全分离（现有 `Notify` 表需扩展发布主体、置顶、回执字段，或独立建表）。
2. **发布主体与认证**：
   - 主体类型：校级 / 院级 / 社团 / 班级，均需后台审核通过并加认证标识（徽章图标 + 主体全称）。
   - 申请需提交主体证明（社团需社长认证身份 + 社团名册）。
   - 未认证主体不得发布公告。**这是与校园墙"冒充官方"风险的直接切割。**
3. **触达规则（两条硬规则）**：
   - **公告不受用户"免打扰"设置影响。** 这是 QQ/微信群做不到的核心差异。
   - 公告在 Feed 顶部以独立卡片呈现（置顶条 + 公告角标），且未读状态持续显示未读角标直到用户确认。
4. **已读回执**：
   - 接收方：公告卡片底部有「已读确认」按钮（勾选项图标）。
   - 发布方：可查看「谁还没看」名单，并对未读人群一键发送提醒。
   - **这条是 B 侧愿意迁移的唯一理由**——辅导员的痛点是"发出去不知道谁看了"。
5. **范围**：公告按学校 / 学院 / 社团 / 班级四级范围下发，不跨校。
6. **边界**：公告区不开放评论（避免沦为撕逼场），疑问引导至私信或圈子帖。

### F11 新用户引导与种子内容

- 注册后 3 步引导（不可跳过第 1 步）：选学校/学院/年级 -> 选 3-5 个兴趣标签 -> 关注 5 个推荐圈子或 10 个推荐人。
- **运营侧种子内容包**：上线前由运营者（本项目为作者本人）预置不少于 50 条真实校内内容，覆盖：食堂测评、选课避坑、校园攻略、失物招领、社团招新。禁止使用占位文案。
- **首条动态官方回应机制**：新用户发布第一条动态后，官方账号在 10 分钟内点赞并留一句具体评论（不是"欢迎"这类空洞话，而是针对内容本身的回应）。这是即刻被验证有效的冷启动手法。
- **空状态设计**：任何列表为空时必须展示引导文案 + 一个可点击的行动按钮，不允许出现空白页。

## 8. 三大缺口的产品解法（G1 / G2 / G3）

本节只写产品层面解法，不含技术实现。

### G1 陌生人破冰 -> F3 免好友搭话

**断在哪里**：现有 `Relation` 只有关注/好友/黑名单三态，`ChatConversation` 需关系成立才可用。"不想加好友又想搭话"这条路径在友声里目前是断的，和微信一样断。

**产品解法**：把"搭话"从"关系的申请"重新定义为"一张有期限的纸条"。

三个关键决策：
1. **不产生关系，只产生对话。** 搭话成功不自动关注、不自动加好友。想加好友是另一个独立按钮。
2. **有共同话题锚点才允许发起。** 锚点是破冰的核心资产——陌生人搭话最难的是"第一句说什么"，系统替用户把这句话的前半句写好。
3. **不回 = 静默消失，无社交负债。** 这一条是产品价值观，也是与微信"添加即永久"的根本分野。

**验收信号**：上线后若"搭话响应率"（收到回复的纸条 / 发出的纸条）低于 20%，说明锚点设计失败，应回到锚点粒度做调整，而不是加大匹配量。

### G2 找搭子 / 兴趣匹配 -> F6 + F7 + F8 + F9

**断在哪里（比预判更严重）**：`User` 无兴趣标签字段、无学校字段；`Circle` 无标签、无简介、无学校；`Activity` 无地点、无标签、无"缺几人"。当前数据结构下"按兴趣找人一起打游戏"是**能力缺失，不是效率不足**。

**产品解法（四层，从数据到界面）**：
1. **标签层（F6）**：用户注册后选 3-5 个兴趣标签（游戏/运动/学习/音乐/摄影/美食/追剧/桌游 等），标签可随时改。圈子同样打标签。
2. **需求层（F7）**：新增"搭子帖"这一结构化内容类型，不是普通帖子。固定四要素：**我要找什么 / 什么时间 / 还缺几人 / 在哪（精确到楼栋或校区，不暴露精确位置）**。示例真实文案："今晚 8 点王者五排，缺 2 个，能开麦，西区宿舍"。
3. **发现层（F8）**：圈子标签化改造后，推荐排序 = 同校 + 标签重合数 + 时间临近 + 距离（校区级）。
4. **闭环层**：从搭子帖和标签检索结果，一键发起搭话（复用 F3）。**形成"看到人 -> 不用加好友 -> 直接搭话"的闭环**，这正是即刻没走通的那条路。

**为什么 G2 排在 MVP 之后**：G2 的终点是搭话。搭话（F3）不先做好，找搭子就是空转——找到人却说不上话，比找不到人更伤。

### G3 官方通知一站触达 -> F5

**断在哪里**：`Notify` 表只有 `type/targetId/postId/actorId/isRead`，是社交事件流，没有发布主体、置顶、回执三个字段。与社交通知混流会重演 QQ 群"重要通知被闲聊淹没"的失败。

**产品解法（三个分离）**：
1. **信息类型分离**：公告 ≠ 通知，独立类型、独立展示区、独立角标。
2. **触达规则分离**：公告豁免用户的免打扰设置。这是与 QQ/微信群的结构性差异，不是体验优化。
3. **反馈闭环分离**：公告有已读回执（发给发布方"谁还没看"名单），通知没有。

**冷启动价值**：G3 是三个缺口里唯一自带 B 侧驱动力的。一个学院把官方通知放上来 = 全院学生必须注册。这是把 500 个用户从 0 变出来的最高效杠杆。

**风险与规避**：官方账号必须审核认证，否则就是校园墙"冒充官方"的翻版——多所高校公开声明严打的正是这一点。

## 9. 明确不做的 Out-of-Scope 清单

每条必带原因。用户预算和时间都有限，本清单不含糊。

| # | 不做的事 | 原因 |
|---|---|---|
| 1 | **App（iOS / Android）** | 用户明确：网页成功后才做。上架需软著 + 备案 + 应用商店审核，周期以月计，与"先跑起来"冲突。Web 已可覆盖全部 MVP 场景 |

| 4 | **直播 / 语音房 / 语音开黑房** | 需《网络文化经营许可证》及音视频相关资质，个人开发者不可承担；且需 7×24 人工审核，与 Fizz"4000 名志愿者审核仍不足"的教训直接冲突 |
| 5 | **完全匿名发帖 / 匿名树洞** | Fizz 因匿名在 UNC 被全校封禁、Trinity 出现学生自杀事件、Bryn Mawr 学生政府投票要求退订；国内校园墙"语言暴力 24.07%""隐私泄露 22.28%"。**本产品只做"校内实名背书 + 对外昵称展示"，不做匿名发布** |
| 6 | **二手交易 / 跑腿 / 校园电商** | 引入资金流与线下纠纷。Fizz 上线 Marketplace 后因"无支付、无评价、无买家保护"成为诈骗温床，其自建数据也显示匿名削弱了信任。本轮无纠纷处理能力 |
| 7 | **跨校 / 全国 Feed** | 单校密度优先。校园推广的基本规律是"一个学校 40% 活跃 胜过 20 个学校 2%"。跨校会稀释校内信息价值——而校内信息价值正是我们区别于微博/知乎的唯一壁垒 |
| 8 | **AI 智能匹配 / 推荐算法** | 冷启动阶段无数据，算法无输入。先用规则（标签重合 + 时间 + 距离），数据够了再说 |
| 9 | **短信验证码注册** | 用户不了解短信服务。补充：短信需签名报备 + 通道费用 + 企业资质，成本高周期长。MVP 用邮箱验证码 + 学号/校园邮箱认证 |
| 10 | **校友 / 毕业生长尾社交** | 目标用户是在校生。校友关系链会稀释"同一时间同一空间"这个校园社交的核心前提 |
| 11 | **私信的语音消息 / 视频通话 / 已读回执（私聊）/ 消息撤回** | 私信已有 WS 实时能力，MVP 只补"免好友搭话"。语音视频带来存储成本与审核成本，撤回与已读在校园半熟人场景会制造社交压力（与"不回应零成本"的价值观冲突） |
| 12 | **课程表导入 / 空教室查询 / 成绩查询** | 超级课程表的教训：一旦从工具切入，用户心智就锁死为工具，社交永远做不起来。且对接教务系统成本高、授权难 |
| 13 | **话题热度榜 / 校园热搜榜** | 冷启动期没有量，榜单是空的，反而暴露冷清。DAU 破 1000 再考虑 |
| 14 | **私信端到端加密** | 与内容安全审核义务冲突，且本轮无合规能力 |

## 10. 验收标准（Given / When / Then）

### F3 免好友搭话

- **AC-F3-1** Given 我是已认证的本校用户 A，When 我在未关注、非好友的用户 B 主页点击「搭句话」并填写一句话发送，Then B 在消息页顶部「待回应」分组看到该纸条，且纸条上显示至少一个共同话题锚点。
- **AC-F3-2** Given B 收到一条搭话纸条，When B 在 24 小时内回复任意内容，Then A 与 B 之间建立正式会话，纸条转为普通会话，且 A 的关注列表与 B 的好友列表均**不发生任何变化**。
- **AC-F3-3** Given B 收到搭话纸条且未做任何操作，When 24 小时到期，Then 纸条从双方界面静默消失，**A 不会收到任何形式的拒绝提示**。
- **AC-F3-4** Given B 对 A 的纸条点了「不感兴趣」，When A 在 7 天内再次向 B 发起搭话，Then 系统拦截并提示"暂无法向该用户搭话"。
- **AC-F3-5** Given 我当日已发起 5 次搭话，When 我发起第 6 次，Then 系统拦截并提示今日次数已用完。
- **AC-F3-6** Given 我要发起搭话，When 系统与对方之间找不到任何共同话题锚点（非同圈子、无共同标签、非同院同届），Then 「搭句话」按钮置灰不可点，提示"暂无共同话题"。

### F5 官方公告

- **AC-F5-1** Given 我是 XX 学院认证发布主体，When 我发布一条范围为"本学院"的公告，Then 该学院全部已认证用户在 Feed 顶部看到置顶公告卡片，且卡片带有主体认证标识。
- **AC-F5-2** Given 用户已开启该应用的消息免打扰，When 一条面向他的公告发布，Then 公告仍然到达并置顶展示，**不受免打扰影响**。
- **AC-F5-3** Given 用户未确认已读，When 他每次打开应用，Then 公告卡片持续显示未读角标直到他点击「已读确认」。
- **AC-F5-4** Given 我是公告发布方，When 我查看公告的回执，Then 我看到已读人数 / 未读人数，且可查看"谁还没看"的具体名单并对未读人群一键提醒。
- **AC-F5-5** Given 一个未通过认证的用户，When 他尝试发布公告，Then 系统拒绝并提示需先完成主体认证。
- **AC-F5-6** Given 一条已发布的公告，When 任何用户查看它，Then 公告下方不显示评论区，仅提供"联系发布方"入口。

### F2 校内身份

- **AC-F2-1** Given 我完成学号或校园邮箱认证，When 我查看自己的主页，Then 展示"已认证 · XX 大学"标识，且页面任何位置都不展示我的真实姓名与学号。
- **AC-F2-2** Given 我是未认证用户，When 我点击他人主页的「搭句话」，Then 系统拦截并引导先完成认证。
- **AC-F2-3** Given 我是未认证用户，When 我发布一条帖子，Then 该帖子在 Feed 中带有"未认证"灰色标识。

### F11 新用户引导

- **AC-F11-1** Given 我是新注册用户，When 首次进入应用，Then 依次经过"学校/学院/年级"、"兴趣标签（选 3-5 个）"、"推荐关注"三步引导，第一步不可跳过。
- **AC-F11-2** Given 我完成引导进入首页，When 首页 Feed 加载完成，Then 至少展示 20 条本校真实内容，不出现空白页。
- **AC-F11-3** Given 我发布了第一条动态，When 10 分钟后我回到该动态，Then 存在官方账号的点赞与一条针对内容本身的具体评论。

## 11. 边界条件

| 类别 | 场景 | 期望行为 |
|---|---|---|
| 空状态 | 新用户首次进入 Feed | 展示引导文案 + 「去看看推荐圈子」按钮，不出现空白页 |
| 空状态 | 圈子内无帖子 | 展示"这个圈子还没有人说话" + 「发第一条」按钮 |
| 空状态 | 消息页无任何会话与纸条 | 展示"还没有人找你搭话" + 「去圈子看看」按钮 |
| 空状态 | 公告列表为空 | 展示"暂无面向你的公告"，不显示占位骨架 |
| 错误状态 | 搭话内容命中敏感词 | 拦截并提示具体命中位置，不清空已输入内容 |
| 错误状态 | 搭话发送失败（网络） | 提示"没发出去" + 重试按钮，纸条保留在草稿 |
| 错误状态 | 认证接口不可用 | 允许跳过认证，用户降为未认证态，功能按限制降级，**不阻断注册** |
| 加载状态 | Feed / 圈子 / 成员列表加载 | 骨架屏，禁止转圈遮罩 |
| 加载状态 | 图片加载 | 懒加载 + 渐显 + 占位底色 |
| 边界值 | 搭话内容长度 | 最少 1 字，最多 50 字，超出禁止输入并提示 |
| 边界值 | 兴趣标签数量 | 最少 3 个，最多 5 个 |
| 边界值 | 每日搭话次数 | 上限 5 次，达到后按钮置灰并提示次日恢复 |
| 边界值 | 搭子帖"还缺几人" | 1-20，超出提示 |
| 边界值 | 公告置顶条数 | 同一用户同时最多 3 条置顶，超出按时间倒序挤掉最早的 |
| 并发 | 多人同时向同一用户搭话 | 纸条按时间入队，不丢失，计数准确 |
| 并发 | 公告已读确认高频点击 | 幂等，重复提交返回成功不报错，不重复计数 |
| 离线 | 断网状态下点击搭话 | 本地提示"网络不可用"，纸条不进入发送队列（不自动重发，避免用户不知情被发出） |
| 离线 | 断网恢复后 | WS 自动重连（指数退避），未读计数重新拉取 |
| 权限拒绝 | 未认证用户发起搭话 | 拦截 + 引导认证 |
| 权限拒绝 | 未认证主体发布公告 | 拦截 + 引导主体认证 |
| 权限拒绝 | 非本校用户查看本校公告 | 不可见（不提示"无权访问"，直接不出现在列表中） |
| 权限拒绝 | 被拉黑用户 | 不能搭话、不能评论、不能查看对方主页内容，且不收到任何提示（静默） |
| 数据边界 | 用户删除账号后 | 其发出的纸条自动失效，已建立的会话对另一方保留但标注"用户已注销" |

### 13.1 必埋事件

| 获客 | `sign_up_complete` | 注册成功 | school, dept, grade, ref, 耗时 | 注册转化率、地推渠道质量 |

| 核心 | `talk_not_interested` | 被标记不感兴趣 | anchor_type | 骚扰率 |
| 核心 | `announcement_published` | 公告发布 | subject_type, scope, 覆盖人数 | B 侧供给量 |

| 留存 | `session_start` | 应用进入前台 | is_new, days_since_reg | DAU / 留存 |
| 留存 | `session_duration` | 会话结束 | duration_sec, page_count | 使用深度 |
| 内容 | `post_created` | 发帖 | circle_id, has_media, content_len | UGC 供给量 |
| 内容 | `comment_created` / `like_created` | 评论 / 点赞 | post_id | 互动率 |
| 安全 | `report_submitted` | 提交举报 | target_type, reason | 举报量（内容健康度） |
| 安全 | `sensitive_hit` | 敏感词命中 | scene(post/comment/talk), 是否放行 | 审核压力 |
| 异常 | `error_occurred` | 前端错误 + API 错误 | code, url, msg | 稳定性 |

### 13.2 实现要求

- 前端封装统一 `trackEvent(event, props)`，底层可切换（自建 / Umami / Mixpanel），先自建最小实现。
- 事件命名规范：`{对象}_{动作}`（如 `talk_sent`、`announcement_read`）。
- 每个事件自动附带公共属性：`user_id`（未登录为匿名 id）、`timestamp`、`device`、`app_version`、`school`。
- **不采集隐私数据**：不上报 IP、不上报搭话/私信的原始文本内容、不上报真实姓名与学号。
- 埋点在数据看板上必须能回答这 4 个数：注册数、认证完成率、**搭话响应率**、**公告已读率**。答不出这四个数等于没埋。

### 13.3 北极星指标与验收线

| 指标 | 定义 | 上线 4 周验收线 | 说明 |
|---|---|---|---|
| 北极星 | **周活跃搭话人数**（一周内至少成功搭上一次话的用户数） | ≥ 150（占 MAU 10%） | 直接对应"找到人说上话"这个第一诉求 |
| 支撑 1 | 搭话响应率 | ≥ 20% | 低于 20% 说明锚点设计失败 |
| 支撑 2 | 认证完成率 | ≥ 60% | 低于 60% 说明认证流程太重 |
| 支撑 3 | 公告已读率 | ≥ 70% | 低于 70% 说明 B 侧不会留下来 |
| 支撑 4 | Day7 留存 | ≥ 30% | 社区产品的生死线 |
| 健康度 | 举报率（举报数 / 内容数） | ≤ 1% | 高于 1% 说明内容失控 |

## 14. 冷启动：第一批 500 个用户从哪来

这是真实需求，不是加分项。以下为可执行路径，按 ROI 排序。

### 14.1 原则：先赢一个学院，不要先赢一个学校

校园推广的基本规律是密度优先——一个学校 40% 的活跃率 胜过 20 个学校各 2%。所以 beachhead 选**作者本人所在的学院**（约 800-1500 人），不是整个学校（2-4 万人）。在 1500 人的池子里拿 500 人，比在 3 万人的池子里拿 500 人容易一个数量级。

### 14.2 时间窗（必须对齐校历）

| 时间窗 | 事件 | 为什么是这个点 |
|---|---|---|
| 开学前 2 周 - 开学第 1 周 | 新生群活跃期 | 新生信息焦虑最强，P2 画像最集中的时刻 |
| 开学第 2-4 周 | 社团百团大战 / 招新 | 社团负责人最痛、最愿意试新工具的时刻 |
| 期中前后 | 活动密集期 | 活动报名与通知需求峰值 |
| 期末 | **避开** | 学生不试新产品 |

**结论：如果现在是学期中段，立刻启动的是"社团侧翼切入"和"地推"两条线，不要等开学季。**

### 14.3 五条路径与 500 人分解

| 路径 | 具体动作 | 预期注册 | 成本 | 关键成败点 |
|---|---|---|---|---|
| **P1 社团/班级侧翼切入（最高 ROI）** | 找 3 个社团的负责人 + 2 个班长，把他们的通知改发到友声官方公告通道。交换条件：给他们"谁还没看"的已读名单（这是他们最想要的东西）。社团成员为了看通知必须注册 | 3 社团 × 60 + 2 班级 × 30 = **240** | 0 元（谈 5 个人） | 已读回执好不好用。不好用他们下周就回群里了 |
| **P2 宿舍楼扫楼** | 作者本人 + 2-3 个同学，按宿舍楼逐间敲门，现场演示"不用加好友就能搭话"，现场注册。每层留 1 个种子用户 | 2 栋楼 × 80 间 × 25% = **120** | 0 元（1 个周末） | 现场必须让人 3 分钟内注册完并发出第一条搭话 |
| **P3 食堂/图书馆门口地推** | 4 场，每场 2 小时，摆桌 + 易拉宝 + 扫码送小礼品（辣条/矿泉水/文具，单价 ≤ 3 元）。拦截 100 人 -> 注册 30-40 人 | 4 场 × 35 = **140** | 约 500 元（礼品 + 打印） | 礼品只是开门钥匙，**现场必须完成注册才送**，否则领完就走 |
| **P4 校园墙合作** | 联系本校表白墙运营者，以"帮你减轻审核与刷屏负担"为交换，请其在投稿回复中引导"也可以直接发在友声"。或在墙下评论引导 | **60** | 0 元 | 校园墙运营者可能视我们为竞争对手。备选：直接以"有审核的第二投稿渠道"定位谈 |
| **P5 自然流入 / 搜索 / 口碑** | 校内 QQ 群、贴吧、小红书本校话题下的自然传播 | **60** | 0 元 | 前四条跑通后自然发生，不是独立动作 |
| **合计** | | **620**（保守取 500） | **约 500 元** | |

### 14.4 第一批内容从哪来（比用户数更容易被忽略的死因）

空社区是社区产品最常见的首日流失原因。上线前必须预置：

- **50 条种子内容**（作者本人写，必须是真实的）：食堂窗口测评 10 条、选课避坑 10 条、校园生活攻略 10 条、社团介绍 10 条、失物招领与问答 10 条。
- **10 个预置圈子**，按本校真实情况命名（如"XX 大学王者荣耀"、"XX 大学跑步"、"XX 大学二手书"），不是通用名。
- **3 条预置公告**（用作者能联系到的真实主体：班级、实验室、一个社团）。
- **上线首周每天真人发 5 条**，不允许有一天是空的。

### 14.5 官方背书（最高杠杆，但要排在最后谈）

如果能拿到 1 个学院或校团委的官方公告授权，全院学生会在一学期内被动注册。这是 G3 的最大价值。
**但不要在 Day 1 去谈**——拿着 0 用户的产品去谈官方合作，成功率接近 0。正确顺序：先用 P1-P4 拿到 300-500 人和真实活跃数据，再拿着数据去谈。

### 14.6 冷启动期的三条纪律

1. **不允许买量、不允许刷量。** 500 个假用户比 0 个用户更糟——它会让所有埋点数据失去意义。
2. **每场地推必须带独立邀请参数**（F12），否则无法归因，下次就不知道该往哪加码。
3. **前两周只看一个指标：搭话响应率。** 注册数是虚荣指标，有 2000 个注册但没人搭上话，这个产品就是死的。

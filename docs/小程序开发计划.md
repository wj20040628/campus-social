# 微信小程序开发计划（路线 C）

> 版本：v1.0（2026-11-02）
> 路线：非个人主体 + 社交-社区/论坛类目 + 小程序备案
> 客户端选型：uni-app（Vue 3）
> 后端：复用现有 Spring Boot API，新增微信登录、内容安全、订阅消息
> 适用范围：友声校园社交平台小程序端 MVP 及后续迭代

---

## 0. 一句话结论

路线 C 不是把 `https://yousheng8.cn` 套进小程序，而是新增一个微信客户端：

- **前置**：非个人主体、社交类目、小程序备案、域名主体一致，四项全部通过后才进入开发交付；
- **客户端**：新建 `miniprogram/` 工程，用 uni-app（Vue 3）重写页面层，复用现有 API 与业务规则；
- **后端**：新增 `user_wechat` 绑定表、微信登录、内容安全、订阅消息，现有 H5 接口保持兼容；
- **MVP**：登录与绑定、信息流、帖子详情、发帖、评论、点赞收藏、私信、通知、个人页、举报、设置；
- **不做**：管理端、支付、直播、匿名发帖、多校多租户、纯 `web-view` 套壳。

按 1 名开发者、每天 4–6 小时估算：**资质就绪后 9–12 周完成 MVP 并提审**；不含主体办理、类目审核、小程序备案的等待时间。

### 1.1 停点规则

出现以下任一情况，暂停 C 路线，不进入开发交付：

1. 微信后台类目页明确要求 B25，而新主体无法取得；
2. 主体无法从个人变更为企业/个体工商户/学校组织；
3. 域名备案主体无法与小程序主体一致，且不愿启用新域名；
4. 小程序备案被驳回且无法在 2 周内补正。

停点后的替代路径：企业主体公众号 + 现有 H5（复用度最高），或继续用微信内 H5。

### 1.2 先确认再投入

在写第一行业务代码前，先在微信公众平台后台完成三件事并截图留档：

1. 「设置 → 基本设置 → 服务类目」查看「社交-社区/论坛」当期资质要求；
2. 「设置 → 基本设置 → 小程序备案」查看所需材料与当前状态；
3. 「开发 → 开发管理 → 开发设置」确认服务器域名配置入口和业务域名入口是否可用。

## 3. 技术方案

### 3.1 客户端选型：uni-app，而不是原生或 web-view

| 方案 | 复用现有代码 | 审核风险 | 工作量 | 结论 |
|---|---|---|---|---|
| 原生小程序（WXML/WXSS） | 低，页面全部重写 | 低 | 最大 | 不选 |
| uni-app（Vue 3） | 中，业务逻辑/API 可复用，UI 重写 | 低 | 中 | **选它** |
| `web-view` 套壳 | 高，几乎零改动 | 高，易判“无实际内容/类目不符”；个人主体不可用 | 最小 | 不选 |

**决策 ADR-MP-001**：用 uni-app（Vue 3）新建独立工程 `miniprogram/`，不与 H5 的 `frontend/` 混编。

理由：

- 现有业务是 Vue 3 + Pinia，页面逻辑和状态管理可以迁移；
- 一套代码可同时构建微信小程序和后续 H5/App；
- 独立工程避免小程序依赖（uni-ui）污染 H5 构建，避免 Element Plus 被打进小程序包；
- 通过 OpenAPI 契约共享接口定义，而不是共享 Vue 组件。

代价：

- Element Plus、`window`、DOM、`vue-router`、`axios` 都不能直接用；
- 页面和样式需要按小程序组件重写；
- 需要单独维护一套小程序 UI。

### 3.3 接口层

- 基础地址：`https://yousheng8.cn/api`，通过 `VITE_API_BASE_URL` 注入；
- 请求封装用 `uni.request`，不用 `axios`（小程序没有 XMLHttpRequest）；
- 统一处理 `{code, message, data}`：`code === 200` 返回 `data`，否则抛业务错误；
- `Authorization: Bearer <accessToken>` 由请求拦截器注入；
- 401 刷新队列与 H5 同思路：单例刷新、失败清登录态、只提示一次；
- 契约来源仍是 `docs/api/openapi.yaml`，新增端点先改契约再写实现。

### 3.4 登录与账号绑定

```text
小程序                         后端                        微信服务器
  │  uni.login()                 │                             │
  │ ── code ───────────────────► │                             │
  │                              │ ── code2Session ──────────► │
  │                              │ ◄── openid/unionid ──────── │
  │                              │                             │
  │                              │ 查 user_wechat              │
  │                              │  ├─ 已绑定 → 签发 JWT       │
  │                              │  └─ 未绑定 → 创建新用户      │
  │ ◄── access/refresh + isNew ── │                             │
  │                              │                             │
  │ 老用户点“绑定已有账号”        │                             │
  │ ── code + 学号 + 密码 ──────► │ 校验 → 绑定 openid → JWT    │
```

关键规则：

- 客户端只传 `code`，绝不传 `openid`；`openid` 只能由服务端 `code2Session` 获得；
- `AppSecret` 只放服务端环境变量，禁止进入小程序包、仓库、日志；
- `session_key` 不落库、不返回；手机号快速验证用 `code` 换手机号的新接口，不依赖 `session_key`；
- 新用户直接创建账号（`status=0`、`onboardingStep=0`），先完成引导再进入信息流；
- 老用户走「绑定已有账号」，校验学号+密码或邮箱验证码后把 `openid` 绑到已有 `user_id`；
- **MVP 不做账号合并**：如果用户误建新号，由管理员在 H5 后台解绑/处理；绑定前明确提示；
- 微信登录只解决身份认证，高风险动作仍受现有「注册满 24 小时 + 信誉分 ≥60」约束，新用户不能立刻发私信/建圈/发集市。

### 3.5 数据模型

新增 `user_wechat` 表，不把 `openid` 塞进 `user` 表：

```sql
CREATE TABLE `user_wechat` (
  `id` BIGINT NOT NULL AUTO_INCREMENT,
  `user_id` BIGINT NOT NULL,
  `app_type` VARCHAR(16) NOT NULL DEFAULT 'mp',
  `openid` VARCHAR(64) NOT NULL,
  `unionid` VARCHAR(64) DEFAULT NULL,
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_app_openid` (`app_type`, `openid`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_unionid` (`unionid`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

约定：

- `app_type`：`mp` 表示小程序，`h5` 预留给后续公众号；
- `openid` 唯一索引保证一个微信身份只绑定一个账号；
- **不做逻辑删除**：解绑时物理删除，避免 `is_deleted` 与唯一索引冲突导致无法重新绑定；
- 不建外键（与 ADR-010 方案 B 一致）；
- `unionid` 只有绑定微信开放平台后才有；没有时允许为空。

### 3.6 WebSocket

现有实现：握手从 query 取 `access_token`，`/ws/chat` 与 `/ws/notify` 两个端点；服务端按 `userId` 广播，不区分端点。

小程序方案：

- 只建 **一条** `wss://yousheng8.cn/ws/chat?access_token=...` 连接，统一处理 `chat` 与 `notify` 事件，避免两条连接重复消息；
- `uni.connectSocket` 返回 `SocketTask`，在 `App.onShow` 重连、`onHide` 关闭；
- 心跳与退避沿用 H5 的 30 秒 ping/pong、1 秒起指数退避；
- 收到消息按 `type + 业务 id + ts` 去重，防止重连窗口内重复；
- 小程序切后台后连接会断，离线提醒改走订阅消息；不承诺“后台常驻在线”。

### 3.7 上传

- MVP 统一走服务端 `POST /api/upload`，字段 `file`，`kind=image|video`，Header 带 `Authorization`；
- 图片先用 `uni.compressImage` 压缩，视频用 `uni.chooseVideo({compressed:true})`；
- 上传进度用 `uploadTask.onProgressUpdate` 展示；
- 服务端已有 25MB 文件上限、32MB Nginx 上限，保持不动；
- OSS 直传放到 P1：`ali-oss` 浏览器 SDK 不能在小程序运行，后续用 OSS 签名直传或 `miniprogram-ci` 方案单独评估；
- 生产 3Mbps 带宽是瓶颈，视频 MVP 默认限制时长/大小，后续接 OSS + CDN。

### 3.8 内容安全

微信要求 UGC 小程序接入内容安全接口。现有项目已有敏感词、审核队列、举报、禁言，但不够：

| 内容 | 检查方式 | 失败策略 |
|---|---|---|
| 帖子/评论/私信/昵称/简介/群名/圈子名/集市标题 | `msgSecCheck`（同步） | 拒绝写入，提示修改 |
| 图片 | `imgSecCheck`（同步，若当前接口可用） | 拒绝上传或转人工审核 |
| 视频 | `mediaCheckAsync`（异步）或人工审核 | 先审后发，MVP 可限制视频入口 |
| 命中敏感词 | 现有 `SensitiveWordFilter` | 保留现有分级：阻断/替换/转审核 |

设计要点：

- 统一封装 `WeChatContentSecurityService`，在写服务入口调用，不散落到 Controller；
- `msgSecCheck` 需要 `openid`，从 `user_wechat` 取；
- 超时 1.5 秒 + 熔断；微信接口不可用时 **fail-closed**（拒绝写入），避免违规内容穿透；
- 不记录完整正文到日志；只记录用户 id、场景、结果、命中类型；
- 审核结果与现有 `review_task`/`audit_log` 打通，管理员仍可在 H5 处置。

### 3.9 订阅消息

- 模板：新私信提醒、评论/回复提醒；模板 id 放环境变量；
- 在用户主动操作时申请订阅：进入私信会话时申请“新消息提醒”，发表评论后申请“回复提醒”；
- 用户拒绝后只保留应用内未读，不重复弹窗；
- 服务端用 `subscribeMessage.send` 发送，`page` 指向小程序内页面；
- 订阅消息是一次性授权，发送一次即消耗；不承诺“永久推送”；
- 系统公告、点赞等低优先级通知只做应用内。

### 3.10 分享与深链

- 帖子详情、个人主页、圈子详情实现 `onShareAppMessage`；
- 信息流/帖子实现 `onShareTimeline`；iOS 是否展示以微信客户端为准，不写死承诺；
- 分享路径带业务 id，例如 `/pages/post/detail?id=123`；
- P1 用 `wxacode.getUnlimited` 生成小程序码，scene 带邀请/帖子 id；
- 小程序内不打开外部网页，避免业务域名与 `web-view` 依赖。

### 3.11 隐私与合规

- 小程序后台填写《用户隐私保护指引》，声明收集：学号、院系/年级/专业、头像、相册/相机、视频、手机号（如启用快速验证）；
- `manifest.json` 开启隐私检查，登录/上传前调用 `uni.requirePrivacyAuthorize`；
- 用户协议、隐私政策做成原生页面，复用现有文案，不通过 `web-view` 打开；
- 注销入口保留，注销后 `user_wechat` 绑定保留但账号 `status=2`，再次微信登录直接拒绝；
- 未成年人保护、举报、屏蔽、禁言入口保留；
- 安全评估按新主体、新增交互渠道重新出具；公安备案主体变更后同步。

### 3.12 管理端

- 小程序不做管理端；
- 举报入口提交到现有 `/report`，管理员在 H5 处置；
- 审核队列、用户封禁、禁言、举报统计继续用 H5；
- 提审时准备管理员测试账号和处置截图，证明内容可管可控。

## 8. 发布与回滚

### 8.1 版本

- 后端：`1.14.0`（新增微信能力，保持向后兼容）；
- H5：继续 `1.13.x`，不需要同步发版；
- 小程序：`1.0.0`；
- 数据库：只增表，不改现有列；迁移脚本随部署包发布。

### 8.2 发布顺序

1. 数据库迁移（`user_wechat`）；
2. 后端部署，`WECHAT_MP_ENABLED=false`，先不开放；
3. 配置 AppID/Secret、模板 id，重启；
4. 打开开关，内部体验版验证；
5. 小程序上传体验版 → 真机验收 → 提审；
6. 审核通过 → 发布；
7. 观察 24 小时登录成功率、5xx、内容安全失败率。

### 8.3 回滚

- 后端：开关置 `false`，小程序登录端点返回“暂未开放”，H5 不受影响；
- 小程序：微信后台回退到上一线上版本；
- 数据库：`user_wechat` 为新增表，回滚不删表，避免丢绑定；如需清理，单独脚本；
- 配置：保留上一版 `.env` 备份。

### 8.4 监控指标

| 指标 | 告警阈值 |
|---|---|
| 微信登录成功率 | 5 分钟 < 95% |
| `code2Session` 失败率 | 5 分钟 > 5% |
| 内容安全失败率 | 5 分钟 > 10% |
| 订阅消息发送失败率 | 15 分钟 > 10% |
| 小程序 API 5xx | 5 分钟 > 1% |
| WebSocket 建连失败率 | 5 分钟 > 10% |

接入现有 Prometheus + `campus-monitor`，不新建一套监控。

## 10. 已拍板的技术决策

| 编号 | 决策 | 理由 |
|---|---|---|
| ADR-MP-001 | uni-app（Vue 3），不用原生/web-view | 复用 Vue 3 与 API 逻辑；web-view 个人不可用且审核风险高 |
| ADR-MP-002 | 独立 `miniprogram/` 工程 | 构建、依赖、包体积、CI 隔离；避免污染 H5 |
| ADR-MP-003 | `user_wechat` 独立表，不存 `session_key` | 支持多端绑定；减少敏感数据；openid 唯一 |
| ADR-MP-004 | MVP 服务端 multipart 上传 | `ali-oss` 不能直接跑在小程序；`uni.uploadFile` 最简单；OSS 直传放 P1 |
| ADR-MP-005 | 内容安全同步 fail-closed | 合规优先；接口故障时拒绝写入，避免违规内容穿透 |
| ADR-MP-006 | 小程序不做管理端 | 管理功能复杂、使用频率低；管理员继续用 H5 |
| ADR-MP-007 | 不做账号合并 | 合并涉及帖子/评论/关系/计数，风险高；MVP 用绑定流程规避 |
| ADR-MP-008 | 单条 WebSocket 连接 | 服务端按 userId 广播，不区分端点；单连接避免重复消息 |
| ADR-MP-009 | 域名优先保留 `yousheng8.cn`，做备案主体变更；变更受阻或超过 2 周则启用新域名 | 保留用户已熟悉的域名与已挂备案号；新域名作为兜底，不让一个环节拖死整体 |

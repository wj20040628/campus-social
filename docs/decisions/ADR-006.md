# ADR-006: MVP 验证码走邮箱 SMTP，短信延后至 v1.1

## Status

Accepted (2026-10-08)

## Background

现有已实现邮箱验证码（`SmtpMessageGateway` / `DevModeMessageGateway` / `VerifyCodeServiceImpl`）与手机号+密码注册。需要判断 MVP 是否必须上短信验证码。

用户背景：短信预算未知，对短信服务申请流程完全不了解。

## 查证结论（有据可查，非推测）

| 厂商 / 产品 | 个人主体能否申请签名 | 依据 |
|---|---|---|
| 腾讯云 短信 SMS | **不能（自用）**。自 2025-09-18 起"不再支持新增个人认证自用资质"；存量个人自用资质不可修改、不可再关联新签名。API 层直接报 `FailedOperation.NotEnterpriseCertification` | 腾讯云公告 `cloud.tencent.com/announce/detail/2127`；资质审核标准 `cloud.tencent.com/document/api/236/108274` |
| 阿里云 短信服务 SMS | **不能（自用）**。个人认证无法通过运营商签名实名报备。仅可用"他用"资质（企业证件 + 授权委托书） | 阿里云帮助中心 `help.aliyun.com/document_detail/108073.html` |
| 阿里云 号码认证 - 短信认证 | **可以**。个人实名认证即可，免资质、免签名报备，用平台赠送签名与模板，仅支持验证码类 | 阿里云帮助中心 `help.aliyun.com/zh/document_detail/3000317.html` |

**价格与周期（阿里云号码认证-短信认证，2025-09-26 调价后）**

| 套餐包 | 价格（一年期） | 折合单价 |
|---|---|---|
| 100 次 | ¥5.4（活动曾低至 ¥3.99） | ¥0.054/条 |
| 1000 次 | ¥54（活动曾 ¥39） | ¥0.054/条 |
| 5000 次 | ¥260 | ¥0.052/条 |
| 1 万次 | ¥500 | ¥0.050/条 |

**审核周期**：
- 传统短信服务：厂商签名审核约 2 小时，但**运营商实名报备另需 7–10 个工作日**（厂商明确未承诺时效）
- 号码认证-短信认证：免签名报备，**可当天开通**

## Decision

**MVP 不做短信验证码，走邮箱 SMTP。短信延后至 v1.1，届时优先选阿里云「号码认证-短信认证」。**

同时采取三项降低损失的措施：

1. **保留手机号 + 密码注册路径**（`AuthController` 已实现），把"验证码"从注册必经路径降级为可选路径。用户不收验证码也能注册。
2. **保留 `MessageGateway` 抽象**（已有 `SmtpMessageGateway` / `DevModeMessageGateway` 两个实现）。v1.1 加一个 `AliyunDypnsGateway` 即可，改动面收敛在 1 个类 + 1 处配置。
3. **本地 dev 模式打印验证码**（`APP_MESSAGE_GATEWAY=dev` 已有），开发调试不依赖外部通道。

## 这个决定的代价（必须说清）

1. **校园场景下手机号比邮箱自然得多**。大学生人人有手机号，但未必有查邮箱的习惯，相当一部分学生的 QQ 邮箱注册后从未登录过。**注册转化率会明显低于短信验证码方案**，这是产品层面的真实损失，不是技术问题。
2. **邮箱通道有发送量上限**。QQ 邮箱未公开 SMTP 日发送上限，社区实测在数十至数百封量级，超限会触发临时限流甚至封停 SMTP 权限。首批几百人集中注册有打爆风险。→ 已列入 `OPEN-DECISIONS.md`，需实测验证。
3. **验证码邮件进垃圾箱是常态**，尤其个人邮箱通过第三方客户端 SMTP 发件。
4. **QQ 邮箱需要手动开启 SMTP 并生成授权码**（16 位，非 QQ 密码），这一步对每个使用者都是个小门槛。

## v1.1 上短信的前置动作（预期 0.5 人日）

1. 阿里云账号完成**个人实名认证**
2. 开通「号码认证服务」
3. 控制台开启「短信认证」开关（不开通接口调用会失败）
4. 引入 SDK：注意是 **`dypnsapi20170525`**（不是传统的 `dysmsapi20170525`）
5. 新增 `AliyunDypnsGateway implements MessageGateway`
6. 用 Credentials 凭据管理，不要把 AK/SK 硬编码

## Consequences

**正面**
- 零成本（QQ 邮箱 SMTP 授权码免费）
- 零资质门槛，个人主体即可
- 零审核周期，MVP 立即可用
- 已有实现，零开发量
- `MessageGateway` 抽象使将来切换通道的成本很低

**负面**
- 注册转化率损失（校园场景尤其明显）
- 邮箱 SMTP 日发送量有上限，规模化前有天花板
- 邮件进垃圾箱导致"收不到验证码"的客诉
- v1.1 需要再做一次接入工作（0.5 人日）与一次回归验证

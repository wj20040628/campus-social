# ADR-002: 部署采用云服务器单机直装（JDK17 + Nginx + MySQL 8.4 LTS + Redis 7）

## Status

Accepted (2026-10-08)

## Background

用户环境事实（硬约束）：
- Windows 10 专业版 21H1 (build 19043)，非正版不可升级 → **装不了 Docker Desktop**，本地 dev 只能直装服务
- 域名备案进行中，服务器尚未购买
- 用户熟悉 Linux 命令 + Java，不了解 Node 生态，不了解容器编排
- 现有仓库已有 `docker-compose.yml` 与两个 Dockerfile（`backend/Dockerfile`、`frontend/Dockerfile.frontend`），但用户从未在本机跑过它们

需要选一条"能真跑起来、用户自己能运维"的部署路径。

## Decision

**采用方案 A：云服务器单机直装。**

服务器上直接 apt/二进制安装：JDK 17 (Temurin) + Nginx 1.24+ + MySQL 8.4 LTS + Redis 7.2，后端以 `java -jar` + systemd 托管，前端 `npm run build` 后由 Nginx 托管静态产物。

明确**不采用**：
- 方案 B（服务器装 Docker）：技术可行，但本地无法验证 compose 文件，见下方 Consequences
- 方案 C（CloudBase 等托管 Serverless）：不匹配用户能力且有供应商锁定

## 三方案对比

| 维度 | A 单机直装 | B 服务器 Docker | C 托管 Serverless |
|---|---|---|---|
| 上手成本 | 低（apt 装 4 个包） | 中（compose 网络/卷/构建上下文，1–2 天） | 高（Node 生态 + 云函数冷启动 + 厂商控制台） |
| 用户能力匹配 | 完全匹配 | 部分匹配 | **不匹配** |
| 本地可复现 | 高 | **低 —— 本机 Windows 无 Docker，永远跑不了** | **极低** |
| 供应商锁定 | 无 | 弱 | **强**（厂商 SDK + 数据库格式 + 计费模型） |
| 排障难度 | 低（`journalctl` / `tail -f`） | 中（多一层抽象） | 高（日志在控制台，本地无法复现） |
| 冷启动 | 无 | 无 | SpringBoot 大包 3–8s，体验差 |
| 月成本 | ¥25–40 | ¥25–40 | ¥100–300 + 数据库另计 |
| 未来扩容 | 手工重复搭建 | 一条命令扩实例 | 厂商托管 |

### 关于"本地无 Docker、服务器有 Docker"的矛盾澄清

这两件事**不冲突**。Windows 10 21H1 装不了 Docker Desktop 只约束**本地开发环境**；服务器是 Linux，装 Docker 完全没问题。所谓"本地直装 + 服务器容器化"的**分裂策略在技术上完全可行**。

**但本 ADR 仍不采用分裂策略**，理由不是可行性，是风险收益比：

1. **compose 文件无人验证**。本地永远跑不了 `docker-compose.yml`，它只能是"看起来对"的状态。事实上它现在就已经出了问题：`docker-compose.yml:36` 用 `redis:7-alpine`，而本地是 Redis 5.0.14.1 —— 这个文件从未被执行过，所以这个分裂一直没被发现。到服务器上第一次跑，排查的是用户从没在本地见过的组合。
2. **收益在 MVP 阶段为零**。容器化的收益是"未来扩容便利"，而 MVP 是单机部署。用户只有一个人，多一层抽象就是多一份排障负担。
3. **目标机型是低配**。compose 里 `JAVA_TOOL_OPTIONS: "-Xms256m -Xmx512m"`（`docker-compose.yml:72`）说明目标是 2G 内存学生机，这个量级下容器化不带来任何收益。

## Consequences

**正面**
- 用户全程在已掌握的技能范围内（Linux 命令 + Java），出问题能自己查
- 本地（Windows 直装 MySQL 8.4 + Redis 5.0）与服务器（Linux 直装 MySQL 8.4 + Redis 7）**同构**，本地跑通的东西上服务器基本能跑
- 排障路径最短：`systemctl status` / `journalctl -u campus-social -f` / `tail -f /var/log/nginx/error.log`
- 无供应商锁定，换云厂商重装即可
- 成本最低，无容器层资源开销

**负面（必须承认）**
- **新人价只有第一年，续费通常翻倍**。做预算按保守价 ¥40/月 规划
- **备案是硬门槛**：未完成 ICP 备案前，云厂商会拦截 80/443 端口，域名无法访问。备案需域名实名 + 负责人核验 + 管局审核，**实际 5–20 个工作日，可能被打回补材料**。这是"买服务器 → 上线"之间不可压缩的等待期
- **单点故障**：服务器宕机 = 服务全停。MVP 接受，但必须做每日 `mysqldump` 异地备份
- **内存紧张**：2核4G 上 MySQL + Redis + JVM 挤在一起。JVM 堆必须固定 `-Xms768m -Xmx1280m`，不能照抄容器里的 512m（那是给 2G 机用的）
- **手工运维**：无健康检查、无自动重启之外的自愈。需配 systemd `Restart=always` + `/actuator/health` 探活（TD-09）
- **未来扩容要重做**：真到需要多实例时，需手工重复搭建或回过头引入 Docker

**对冲措施**
- 上线前跑一次"从本地 9.0 用 mysqldump 导出 → 导入服务器 8.4"的完整演练（见 ARCHITECTURE.md §11，环境一致性验证）
- 每日 `mysqldump` + 异地保存，写进 crontab 并验证恢复过一次
- 云安全组只放行 22/80/443；MySQL/Redis 只监听 127.0.0.1
- systemd unit 配 `Restart=always`、`MemoryMax=1600M`

# ADR-003: 全项目图标锁定 @element-plus/icons-vue 2.3.2，禁止引入第二套图标库

## Status

Accepted (2026-10-08)

## Background

团队级 P0 规则要求：架构文档中必须锁定一套 SVG 图标库，前端依赖随之锁定，全项目统一不得混用；禁止 emoji 作为功能图标。

前端已用 Element Plus 2.14.5（package-lock 实测解析版本）；`@element-plus/icons-vue@2.3.2` 已存在于依赖树（作为 element-plus 的直接依赖被传递进来），且已被 11 个文件引用。

需要裁决：继续用 EP icons（零新增依赖），还是换独立图标库（lucide-vue-next / Iconify 等，视觉更精致）。

## Decision

**锁定 `@element-plus/icons-vue`，精确版本 `2.3.2`。不引入 lucide-vue-next 或任何第二套图标库。**

**必须同步执行的动作**：`@element-plus/icons-vue` 当前是**传递依赖**（靠 `element-plus@2.14.5` 带进来，见 `package-lock.json:1421`），并未声明在 `frontend/package.json` 的 `dependencies` 中。一旦 element-plus 升级或调整依赖结构，它会消失导致构建失败。**必须把它提升为直接依赖并锁 `2.3.2`**。

```json
// frontend/package.json —— dependencies 中新增
"@element-plus/icons-vue": "2.3.2"
```

### 尺寸规范

与 `docs/design/design-tokens.json` 的 `icon.sizes` 保持一致：

| 档位 | 值 | 用途 |
|---|---|---|
| inline | 16px | 行内图标、标签内、密集列表 |
| inButton | 20px | 按钮内、表单控件前后缀 |
| standalone | 24px | 独立操作区、空状态、导航项 |

EP icons 以 `1em` 渲染，通过 CSS `width`/`height` 设尺寸（**不改 viewBox**）。**禁止在模板里写死像素值**，一律走设计令牌的 CSS 变量。

### 风格契约

`viewBox="0 0 1024 1024"` + `fill="currentColor"`（EP icons 是**填充型**图标，不是描边型）。

### 允许的自绘补齐（不构成"混用"）

设计师实测 EP 图标库共 **294 个**图标，缺 3 个本产品必需的语义，允许在 `src/icons/` 下自绘补齐，**前提是严格遵循同一风格契约**（1024 viewBox + `fill="currentColor"`）：

| 文件 | 语义 | 原因 |
|---|---|---|
| `IconLike.vue` | 点赞（空心/实心两态） | EP 无 thumbs-up |
| `IconShield.vue` | 管理与审核 | EP 无 shield |
| `IconSend.vue` | 发送（纸飞机） | EP 无 send，`Promotion` 是喇叭，已被"官方通知"占用 |

除这 3 个之外，任何新增自绘图标都必须先提需求给设计评审。

## 裁决理由

1. **零新增体积**：已在依赖树、已在打包产物里。换 lucide 是净增（tree-shaking 后约 20–40KB/百图标 + 运行时组件包装）。
2. **视觉一致性是硬约束，不是审美偏好**：Element Plus 组件内部（输入框清除叉、下拉箭头、日期选择器日历、消息弹窗、分页器箭头）已经在用这套图标。若业务代码用 lucide（描边型、24 viewBox），同一页面会同时出现填充型与描边型两套视觉语言 —— 这正是"混用"最典型的翻车现场，而混用是 P0 明令禁止的。
3. **尺寸与风格体系天然对齐**：EP icons 与 EP 组件内图标同源（同为 1024 viewBox 填充型），不需要额外的换算层或视觉调和层。
4. **学习成本为零**：团队已在用（11 个文件），不需要再记一套命名体系。

> 设计师在 `docs/design/design-tokens.json` 中独立得出同一结论（同一库、同一版本 2.3.2、同一尺寸档位），并实测图标总数 294 个。本 ADR 与该文件互为准绳。

## Consequences

**正面**
- 零新增依赖、零新增体积、零学习成本
- 全项目图标视觉语言统一，不会出现"两个风格的箭头"
- 与 Element Plus 组件内图标天然一致
- 294 个图标覆盖社交场景大部分语义（评论/定位/日历/用户/设置/搜索/通知/星标）

**负面（必须承认）**
- EP icons 是"够用"而非"精美"，风格偏中性，做不出有个性的品牌视觉
- **294 个图标存在明确表达缺口**：点赞（无 thumbs-up）、审核/管理（无 shield）、发送（无 send）三个本产品核心语义都缺失，必须自绘补齐（见上方"允许的自绘补齐"）
- 其他社交语义（"搭子"、"破冰"、"已读回执"）也无现成图标，需要用现有图标组合表达，语义传达会打折
- 若 v2 要做品牌化视觉升级，需整体替换 —— 替换成本约 1–2 人日（11 个文件的 import + 全局注册 + 3 个自绘图标）

**执行约束（写进 Spec 的硬规则）**
- 全项目图标仅来自两处：`import { X } from '@element-plus/icons-vue'`，或 `src/icons/` 下经设计评审的自绘图标
- 尺寸只允许 16 / 20 / 24 三档，走设计令牌的 CSS 变量，禁止模板里写死像素
- 自绘图标必须遵循 `viewBox="0 0 1024 1024"` + `fill="currentColor"`，否则视为引入第二套图标库
- **禁止任何 emoji 字符作为功能图标**。当前已知违规点必须修：
  - `frontend/src/views/Chat.vue:150` —— 附件图标用了 emoji
  - `frontend/src/views/Notify.vue:103` —— 星级图标用了字符
- 需要新图标时，提需求给设计评审，**不得私自引入第二套图标库**

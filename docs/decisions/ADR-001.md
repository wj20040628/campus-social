# ADR-001: 在现有 campus-social 工程上增量改造，不推倒重写

## Status

Accepted (2026-10-08)

## Background

「友声 · 校园生活社区」要在真实校园推广，需补齐三个缺口（陌生人破冰私信、按兴趣找搭子、官方公告一站触达）并上线部署。现有工程已完成度较高：SpringBoot 3.2.5 单模块、12 个 Controller、23 张表、JWT 双 token、Spring 原生 WebSocket、敏感词 DFA、审核流、前端 16 个页面（磁盘实测，见 ARCHITECTURE.md §2.1）。

摆在面前两条路：在现有工程上增量改造，或推倒重来。

决策约束（硬约束，不是偏好）：
- 用户只会 Java SpringBoot，不熟悉 Node/Python 后端
- 用户有毕设复用动机，希望代码的成长能积累
- 需要赶本学期推广窗口，交付周期敏感

## Decision

**在现有工程上增量改造。**

不更换编程语言、不更换后端框架、不更换前端框架、不重新分层、不重建数据库。

具体范围：
- 新增 7 张表（report / interest_tag / user_tag / buddy_post / buddy_join / announcement / announcement_read）
- 新增 3 个业务域（ReportService / BuddyService / AnnouncementService）
- 改造 1 个既有端点（`/chat/send` 加护栏）
- 修复 10 项 D1 技术债（TD-01 ~ TD-10）

## Consequences

**正面**
- 交付周期最短。三个缺口预估 6–9 人日，若重写需 25–35 人日（存量能力重建）
- 用户全程在自己熟悉的技术栈内工作，不存在"边学边写"的交付风险
- 现有可验证能力（鉴权、WS 推送、审核、敏感词、防超卖）直接继承，这些是最容易写错的部分
- 毕设可复用完整的 23→30 表演进过程，有据可查
- 数据库演进有迁移脚本（`sql/migration_*.sql` 已有 6 个），增量路径已被验证

**负面（必须承认）**
- 承接 10 项 D1 技术债，其中 TD-01（CORS 全开）、TD-02（WS origin 全开）是安全问题，必须上线前修
- 承接 9 项 D2、4 项 D3 债务，长期维护成本高于新工程
- 单模块 Maven 工程在代码量到 5 万行后编译与定位变慢，未来拆分有成本
- `README.md` 与实际代码已存在偏差（TD-11：声明 Redis 6+，实际本地 5.0），说明文档同步纪律缺失，增量过程中可能继续累积偏差
- 早期设计取舍（如 Feed 同步写扩散、媒体存本地磁盘）被继承，短期无法摆脱

**风险与对冲**
| 风险 | 对冲 |
|---|---|
| 增量改造引入回归 | 端到端验证步骤（ARCHITECTURE.md §11）必须跑通，含"Redis 5.0 上全流程"这一条 |
| 债务越积越多 | D1 列为上线阻断项，不做完不放行；D2 排进 MVP 内 |
| 文档与代码继续失同步 | ADR 与 ARCHITECTURE.md 作为活文档，实现与文档冲突时先改文档再改代码 |

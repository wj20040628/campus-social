# ADR-007: MVP 完全不接入支付

## Status

Accepted (2026-10-08)

## Background

MVP 三个场景 —— 陌生人破冰私信、按兴趣找搭子、官方公告一站触达 —— 没有任何一环涉及资金流转。

用户背景：短信/支付预算未知，对支付接入流程完全不了解，域名备案进行中。

需要给出明确判断，并把"将来要接支付需要什么"讲清楚，让用户心里有数。

## Decision

**MVP 完全不接入任何支付。写入 Out-of-Scope。**

不做微信支付、不做支付宝、不做虚拟货币/积分体系、不做任何需要资金流转的功能。

## 理由

- **需求上不需要**：三个首发场景没有一个是付费场景。为不存在的交易建支付链路是纯粹的前置浪费。
- **成本上不划算**：支付接入的真实成本不在代码（约 3–5 人日），而在**主体资质、合规、对账、退款、资金安全**这一整套。对一个尚未验证需求的产品，这些是净负担。
- **门槛在合规不在技术**：见下表的"主体"一行 —— 这才是真正的墙。

## v2 接入微信支付的前置条件（让用户心里有数）

| 前置项 | 要求 | 难度 |
|---|---|---|
| **经营主体** | 微信支付主体类型分 小微 / 个体工商户 / 企业 / 党政机关 / 其他组织。**小微**（无营业执照）可用个人身份证 + 结算银行卡申请，但**收款限额低**（如信用卡日累计约 ¥1000） | 中 |
| **线上支付场景** | PC 网站支付、JSAPI 等线上场景**通常不向小微开放**，需个体工商户或企业营业执照 | **高 —— 这是真正的门槛** |
| 已备案域名 | 经营场景需提供已备案域名；PC 网站场景需提交网站备案信息 | 中（备案已在做） |
| 结算账户 | 企业须对公账户；个体工商户可选法人个人储蓄卡 | 低 |
| 超级管理员 | 需法定代表人或经办人的实名微信，且需刷脸验证 | 低 |
| 审核周期 | 资料审核 1–3 个工作日 + 签约审核 1–2 个工作日 | 低 |
| 费用 | 无开户费 / 无年费；交易费率约 0.6%（服务商渠道可谈至 0.2%） | — |

**一句话给用户**：微信支付不卡在技术上，卡在**主体资质**。个人身份最多拿到小微商户（限额低、且多数线上支付场景不开放），要做真正的线上收款，得先注册个体工商户或公司。**这是 v2 的事，现在别花心思。**

## Consequences

**正面**
- MVP 无需处理资质、对账、退款、资金安全、风控，交付范围显著收敛
- 无需 ICP 经营性备案（非经营性备案即可）
- 无资金合规风险
- 代码里不存在支付相关的攻击面

**负面（必须承认）**
- 若将来产品方向转向"活动收费 / 打赏 / 会员"，需要一次性补齐主体资质，**这个周期以周计**（注册个体工商户 + 微信支付进件 + 签约），不是加个 SDK 就能上
- 现在不做意味着数据库里不会有 `order` / `payment` / `refund` 表，将来加需要一次数据迁移
- 若 v2 一定要做，建议提前在 `user` 表预留主体相关字段（当前无此需求，不预留，避免过度设计）

**缓解措施**
- 在 `OPEN-DECISIONS.md` 登记 OD-02（v2 是否转向商业化），作为产品方向待确认项
- 若 v2 确认需要支付，建议以个体工商户主体申请，成本约数百元 + 1–2 周

## 二、我自己的失误（8 项）

### 1. 派发方式错误：契约改动被代码实现挤掉

**现象**：第一次派发后端时说「改契约 + 写实现」，后端只写了代码，`openapi.yaml` 一字未动，解析逻辑零实现。

**根因**：一个 prompt 里放了两件有先后依赖的事，代理把优先级给了写代码。

**解法**：拆成两次派发。后续我先把契约定稿提交（`d22c80f`），再派实现。

---

### 2. 假绿门禁：检查命令算的是整行长度

**现象**：`awk` 报 `JWT_ACCESS_SECRET=已填(86 字符)`，我据此判断「86 > 64 够了」，放行。

**根因**：86 是**整行长度**，含`JWT_ACCESS_SECRET=` 这 18 个字符前缀，实际密钥只有 67 字符，不满足 64 字节要求。**我只看了「大于 64」而没减去前缀。**

**解法**：`sed` 重新生成密钥后仍失败，才抓到真实报错 `jwt.access-secret 至少 64 字节(96 字符 base64)`。

**教训**：检查「长度是否达标」时，必须算**值本身**的长度，不是整行。

### 3. 自检注入无效：因为 pattern 还原得太早

**现象**：新写的门禁脚本 `--self-test` 输出「注入 3 项，捕获 0 项」。

**根因**：
```python
PATTERN = bad_pattern
cases.append(("名字", check))   # ← 注入
PATTERN = origin               # ← 立刻还原
# ↓ for 循环才开始真正调 check()
```
三次注入在`check()` 真正执行前就被还原了，等于没注入。

**解法**：把 pattern 存进用例表，在循环内才赋值给全局。

**教训**：自检本身也会有假绿。如果当时我的退出码逻辑写成「有失败才返回 1」，这版自检会永远显示通过。

### 6. 宝塔装的 MySQL，root 走auth_socket

**现象**：改成 `062828` 仍然 Access denied。

**根因**：
```bash
mysql -e "SELECT user,host,plugin FROM mysql.user WHERE user='root';"
# root  localhost  auth_socket    ← 认系统账号，不认密码
```
`auth_socket` 意味着**输任何密码都不看**，只有用 root 系统账号登录服务器的人能连。systemd启动的Java 进程当然连不上。而宝塔那个「修改root 密码」框里显示的值是无效摆设。

**解法**：建专用账号（用密码认证）：
```sql
CREATE USER 'campus'@'localhost' IDENTIFIED BY 'Campus@2026Db';
GRANT ALL PRIVILEGES ON campus_social_v2.* TO 'campus'@'localhost';
```

**教训**：宝塔装的 MySQL，应用必须用独立账号，不能用 root。

### 7. IP 敲错，导致约 1 小时的无效排查

**现象**：`curl http://120.26.46.6/` 返回 Tomcat 页面，而 `curl -H "Host: 120.26.46.6" http://127.0.0.1/` 返回我的应用。

**根因**：真实公网 IP 是 `120.26.4.66`（`4.66`）。我用了 `120.26.46.6`（少一个 6）和 `120.26.46.66`（多一个 6），**两个都是不同的机器** —— 前者恰好有 Tomcat，后者返回 Nginx 404。

### 8. 给了太多复杂命令，导致粘贴事故

**现象**（连续发生 4 次）：
- `read -rsp "..." DBPW` 吃掉粘贴的下一行 → 密码变成了下一条命令本身
- 两条命令粘成一行 → `.envsed` 被当成文件名
- `cat <<EOF | tr -d '\n')` 多出括号 → 表达式未结束
- 系统配置 `After=...Wants=...` 粘成一行

**根因**：命令里堆了 `sed`、`$(...)`、引号嵌套、heredoc，终端粘贴时换行/特殊字符极易被吃掉。

**解法**：涉及密钥一律用宝塔面板的文件编辑器手动填；命令超过一行就用 `&&` 串成单行。

## 三、环境配置问题（5 项）

### 9. JWT 密钥长度不足

`spring-boot` 要求 HS512 密钥至少 64 字节（base64 需 96 字符）。最初的值不够长。改用 `openssl rand -hex 48`（96 个十六进制字符，**不含 `/` `+` `=**，适合通过 sed 注入）重新生成。

> 附带教训：`openssl rand -base64 64` 产生的串含 `/`，而 `/` 是 sed 替换串的分隔符，会直接打断表达式。**塞进 sed 就必须用 `-hex`。**

### 10. 线上数据库只有空库

服务器上执行的是 `CREATE DATABASE campus_social_v2`，只有库没有表。程序启动到「加载敏感词」时炸了：
```
Table 'campus_social_v2.sensitive_word' doesn't exist
```

**解法**：从本机 3306 库`mysqldump` 导出完整结构与数据（31 张表），上传后导入。

> 附带坑：在 PowerShell 里跑 `mysqldump` 要用 `| Out-File`，`>` 在 PS 里是追加重定向且会报语法错误。**cmd 窗口可以直接用 `>`。**

### 11. systemd 无限制重启，烧满 CPU

`Restart=on-failure` + `RestartSec=10`，启动失败就无限循环。日志显示 **restart counter 涨到 40**，每轮消耗 43 秒 CPU，宝塔面板首页显示 99% 负载。

**解法**：
```ini
# /etc/systemd/system/campus.service.d/limit.conf
[Service]
StartLimitIntervalSec=300
StartLimitBurst=3
```
5 分钟内失败 3 次就不再尝试。

### 12. `Restart=on-failure` 把「启动慢」伪装成「故障」

服务启动需约 43 秒（1 核机器上JIT 预热 + 数百个类加载）。期间 `systemctl is-active` 显示 `activating`，端口未开。我一度以为是内存不足/OOM。

**解法**：认清这个机器的启动时间预期，前台运行观察真实输出，不要用 `systemctl status` 的中间态判断死活。

### 13. 宝塔会覆盖自己管理的 Nginx 配置

我改 `/etc/nginx/sites-enabled/default`（软链到 `sites-available/default`），reload 后确实生效；但宝塔面板检测到配置变更后会重新生成该文件，**把内容冲回`root /var/www/html`**。

**正确做法**：走宝塔面板 → 网站 → 设置 → 根目录，而不是直接改文件。

## 四、验证方法上的错误（3 项）

### 14. 只看 HTTP 状态码，不看返回内容

今天至少 **3 次**「200 但返回的不是我的应用」：

| 场景 | 状态码 | 实际返回 |
|---|---|---|
| Nginx 欢迎页 | 200 | `Welcome to nginx!` |
| 宝塔默认站点 | 200 | Tomcat 演示页 |
| 错误IP | 404 | 另一台机器的 Nginx |

**教训**：**验证部署必须看返回内容，不能只看状态码。** 200 只说明「有响应」，不说明「是我的应用」。

### 15. 前台运行没加载 `.env`，报错全是误导

第一次前台跑 `java -jar campus-social.jar` 时报 JWT 密钥错误，但 `.env` 里密钥明明有 96 字符。

**根因**：systemd 配置里有 `EnvironmentFile=/opt/campus/.env`，**手动运行时不会自动加载**。JVM 拿到的环境变量是空的，于是先在 JWT 校验处炸掉，**根本走不到数据库那一步**。

**解法**：
```bash
cd /opt/campus && set -a && . ./.env && set +a && java -jar campus-social.jar --server.port=8080
```
`set -a && . ./.env && set +a` 把文件里的变量导出到当前 shell。**改完 `.env` 必须重启服务才生效**，这一点我一开始也忘了。

### 16. 只查了「有没有配置」，没查「配置对不对」

`.env` 里 `MAIL_PASSWORD` 填了但那个授权码已泄露进 bash 历史。检查项只看了「非空」，没看「是否该用」。

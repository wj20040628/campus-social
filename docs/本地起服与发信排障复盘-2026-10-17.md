- 账号体系重构前端收尾：学号变主账号、记住我（勾 7d / 不勾 3d）、邮箱仅作安全凭证（找回密码/绑定/次要登录）、手机取消。已落盘且 `vite build` 绿。

- `user` 表 `email` 列迁移已在本机 MySQL 执行完成，账号重构 DB 前置就绪。

### 1.2 阿里云邮件发信改造（生产侧）

### 1.3 本地起服排障（本轮焦点）
- 终端 `mvn spring-boot:run` 连跪两轮：`jwt.access-secret 至少 64 字节` → `Access denied for user 'Administrator'@'localhost'`。当时误判「本地没有 application-local.yml，所以要手注 env」。
- `POST /auth/send-code` 返回 500：根因是 Redis 没起（邮件是 `@Async` 不影响 HTTP，同步链第一个操作就是碰 Redis，懒连接才暴露）。
- `BeanNotOfRequiredTypeException ... $Proxy131`：`@EnableAsync` 默认 JDK 接口代理，与网关 `@Lazy 具体类 self` 自注入冲突。改 `proxyTargetClass=true` 一次修两处（aliyun + smtp 网关共病）。
- 阿里云模板发信本地实测成功，但验证码渲染成 `$621085`（模板多一个 `$`），用户去控制台删掉后复测得 `389319` 干净邮件，**全链路闭环**。
- 用户质问「为什么终端要配一堆 env，项目里明明有，我一直用 IDEA 一键启动」——这是**关键纠正**，详见第 6 节。核实结论：`application-local.yml` 真实存在且 gitignored，IDEA 因 `ACTIVE_PROFILES=local` 加载它；终端失败是漏 profile，不是缺配置。
- 按用户「你帮我写吧」要求，把 `application-local.yml` 的 `message-gateway: dev` 改成 `aliyun` + 加 `aliyun` 块（取 PowerShell 历史里的 mail-sender AK，去前导空格），让一键启动也能真收邮件。
